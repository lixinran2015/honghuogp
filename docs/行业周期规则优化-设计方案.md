# 行业周期规则优化 — 设计方案

在 [行业周期规则优化-数据来源.md](./行业周期规则优化-数据来源.md) 基础上，给出可落地的数据结构、采集流程与规则改造方案，按阶段实施。

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         cycle_data_YYYYMMDD.json                         │
│  (现有) macro, industry_index, money_flow, industry_revenue_yoy,         │
│         industry_net_cash_dist                                           │
│  (新增) industry_float_mv, industry_forecast_risk, industry_capex_yoy,   │
│         (可选) real_estate_l2                                            │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    industry_cycle_rule_engine.py                         │
│  build_*_map() 读取新字段 → suggest_cycle() 增加分支与阈值               │
└─────────────────────────────────────────────────────────────────────────┘
```

- **采集**：在 `collect_industry_cycle_data.py` 中增加 1～4 的采集函数，写入 cycle_data 新字段；缺数据时字段为空/缺省，规则引擎兼容。
- **规则**：在 `suggest_cycle()` 及 `run_suggestions()` 中按「有则用、无则退化为现逻辑」接入新指标。

---

## 二、数据层设计

### 2.1 cycle_data 扩展字段（JSON）

| 字段名 | 类型 | 说明 | 对应优化项 |
|--------|------|------|------------|
| `industry_float_mv` | `[{ "industry": "申万一级名", "float_mv_wan": 1234567, "trade_date": "YYYYMMDD" }]` | 各行业当日流通市值（万元），与 industry_index 同口径 | ① 相对资金 |
| `industry_forecast_risk` | `[{ "industry": "申万一级名", "report_period": "20251231", "pre_dec_pct": 0.25, "pre_loss_pct": 0.1, "sample_count": 40 }]` | 当报告期该行业业绩预告中预减+首亏占比等 | ② 业绩预告 |
| `industry_capex_yoy` | `[{ "industry": "申万一级名", "capex_yoy_pct": -5.2, "sample_count": 30 }]` | 行业 Capex 同比（%），按成分股聚合 | ③ 资本开支 |
| `real_estate_l2` | `[{ "l2_name": "房地产服务Ⅱ", "l2_code": "801181.SI", "constituents": ["ts_code1", ...] }]` | 房地产下申万二级列表及成分（可选，用于子板块规则） | ④ 房地产子板块 |

- `industry_index` 与 `industry_float_mv` 均按**申万一级**，用 `ts_code`（如 801010.SI）或 `name` 与现有 `SW_INDUSTRY_MAP` 对齐。
- 资金流向为同花顺口径，需继续用现有 `SW_TO_THS_MONEYFLOW` 汇总到申万一级；相对资金 = 资金净流出(亿) / (float_mv_wan/10000)。

## 三、分项方案

### 3.1 ① 相对资金：资金净流出 / 行业流通市值

**采集**

- 在 `collect_industry_cycle_data.py` 中新增 `collect_industry_float_mv(pro, rate_limiter, trade_date)`。
- 调用 `pro.sw_daily(trade_date=trade_date, fields='ts_code,name,float_mv,total_mv')`，取**申万一级**（仅保留与现有 `SW_INDUSTRY_MAP` 中 ts_code 对应的行，或按 name 过滤一级行业）。
- 输出列表：`{ "industry": name, "float_mv_wan": float_mv, "trade_date": trade_date }`，写入 `data['industry_float_mv']`。
- `trade_date` 取当日或最近交易日；若 sw_daily 无当日则用最近有数据的日期。
- **依赖**：Tushare 5000 积分；无权限时该列表为空，规则退化为当前绝对值逻辑。

**规则引擎**

- 新增 `build_industry_float_mv_map(cycle_data) -> Dict[str, float]`，返回 行业名 -> 流通市值（**亿元**，float_mv_wan/10000）。
- 在 `suggest_cycle()` 中增加可选参数 `float_mv_亿`。
- **资金判下滑**处（当前 `moneyflow_5d < -50`）增加分支：
  - 若存在 `float_mv_亿` 且 `float_mv_亿 > 0`：计算 `outflow_ratio = abs(moneyflow_5d) / float_mv_亿`；
  - 若 `outflow_ratio >= 0.01`（1%），则判下滑，原因写「资金5日净流出占流通市值 X.X%」；
  - 否则若 `moneyflow_5d < -50` 仍用原绝对值规则（兼容无市值数据）。
- 配置化：阈值 0.01 写为常量（如 `MONEY_OUTFLOW_RATIO_DECLINING = 0.01`），便于后续调参。

**实施顺序**：先采集 + 写入 cycle_data，再在规则中接 float_mv；最后可考虑「绝对值与比例二选一或同时满足」的策略（见下节可选策略）。

---

### 3.2 ② 业绩预告 / PMI 前瞻

**采集**

- 新增 `collect_industry_forecast_risk(pro, rate_limiter, report_period)`（如 report_period='20251231'）。
  - 若积分≥5000：`pro.forecast_vip(period=report_period, fields='ts_code,type')` 全市场；
  - 否则：用 `pro.forecast(period=report_period)` 按需抽样或按已维护股票列表拉取。
- 用现有**申万行业成分**（从 `index_member_all` 或 sync 后的 dim_stock.industry）将每只股票归到申万一级行业。
- 按行业汇总：该行业成分股中 `type in ('预减','首亏','续亏','略减')` 的占比 `pre_dec_pct`，以及 `type in ('首亏','续亏')` 的占比 `pre_loss_pct`，样本数 `sample_count`。
- 写入 `data['industry_forecast_risk']`，格式见 2.1。
- **PMI**：已写入 `macro.pmi`，规则层按需读取；可在 suggest 结果中增加「宏观景气」标签（如 PMI<50 时对部分行业提示），不强制改周期。

**规则引擎**

- 新增 `build_industry_forecast_risk_map(cycle_data) -> Dict[str, dict]`，返回 行业 -> `{ "pre_dec_pct", "pre_loss_pct", "sample_count" }`。
- 在 `suggest_cycle()` 中增加可选参数 `forecast_risk`。
- **不改主周期结论**，仅做辅助：
  - 若某行业当前判为**上升期**，但 `pre_dec_pct > 0.3` 或 `pre_loss_pct > 0.15`，则在 `reason` 后追加「（业绩预告预减/首亏占比较高，建议关注）」；
  - 或在 suggest 输出中增加字段 `warning_forecast: true`，供前端展示。
- 可选：PMI<50 时对「营收 0～10% 且判成熟期」的行业，reason 中追加「PMI<50，宏观偏弱」。

**实施顺序**：先实现采集与 cycle_data 写入；规则层先做「仅追加提示」，再视需要做「PMI 修正」分支。

---

### 3.3 ③ 成熟期 + 资本开支（Capex）

**数据来源**

- 单股 Capex：Tushare `cashflow(ts_code, period, fields='ts_code,end_date,c_pay_acq_const_fiolta')`，`c_pay_acq_const_fiolta` 为购建固定资产等支付的现金（元）。

**采集**

- 方案 A（推荐）：在**现有 fact_fundamental 或财务 ETL** 中增加 capex 字段（从 Tushare cashflow 表按报告期取数），再在行业周期采集里按**申万行业**聚合。
- 方案 B：不在库表落 Capex，仅在 `collect_industry_cycle_data.py` 中按「申万行业成分股」循环调用 `pro.cashflow`，按报告期聚合行业 Capex 同比。需限频与批处理，避免单股单次调用过多。
- 聚合方式：按行业对成分股最近两期 Capex 求和或取中位数，算 YoY（%），得到 `industry_capex_yoy` 列表，格式见 2.1。

**规则引擎**

- 新增 `build_industry_capex_yoy_map(cycle_data) -> Dict[str, float]`。
- 在判定**成熟期**时（营收 0～10% 分支）增加可选逻辑：
  - 若 `capex_yoy` 存在且 `capex_yoy < -10`（同比降幅>10%）：在 reason 中追加「Capex 同比下行，成熟期特征」；或维持成熟期结论不变，仅丰富说明。
  - 不在本阶段用 Capex 强制改周期（避免误伤扩张期行业），仅作「成熟期置信度」增强。

**实施顺序**：先定 Capex 数据来源（方案 A 需 ETL 支持）；再实现行业聚合与 cycle_data 写入；最后在规则中做成熟期理由增强。

---

### 3.4 ④ 房地产子板块（保障房、商管等）

**采集**

- 一次性或定期拉取申万房地产下 L2/L3 列表：`pro.index_classify(level='L2', src='SW')`，过滤 `name` 或 `parent` 为房地产的一级下的二级；同理可拉 L3。
- 写入 `data['real_estate_l2']`：`[{ "l2_code", "l2_name", "constituents": [ts_code, ...] }]`，成分由 `index_member_all(l2_code=...)` 得到。
- 可选：在 dim_stock 或单独映射表中增加 `industry_l2` / `industry_l3` 字段，由 sync 脚本按 `index_member_all(ts_code=...)` 回填，供选股与规则共用。

**规则引擎**

- 当前逻辑：行业为「房地产」时一律判下滑期。
- 扩展逻辑：
  - 若配置或 cycle_data 中存在房地产 L2 列表，且当前处理的是**一级行业「房地产」**：
    - 可选 A：对「房地产」一级仍统一判下滑期，但在 suggest 输出中增加 `real_estate_l2_detail`，列出各二级（如房地产服务Ⅱ、房地产开发Ⅱ）及成分股数量，供人工或后续规则细化。
    - 可选 B：规则引擎支持「按二级行业出建议」。即 YAML 或配置中允许出现二级行业名（如「房地产服务Ⅱ」），run_suggestions 遍历时同时遍历一级与配置的二级；对「房地产服务Ⅱ」等子板块**不**执行「房地产单独降级」，仅用通用规则（营收+资金）；对「房地产开发Ⅱ」等仍可单独降级或保持下滑。
- 建议先做可选 A（只落数据与展示），再视需求做可选 B（配置 + 规则分支）。

**实施顺序**：先查申万 2021 房地产下 L2/L3 名称与代码；实现 `real_estate_l2` 采集与写入；再在规则/前端做「房地产子板块」展示或分支。

## 四、采集脚本改造清单

| 步骤 | 文件 | 内容 |
|------|------|------|
| 1 | `collect_industry_cycle_data.py` | 新增 `collect_industry_float_mv(pro, rate_limiter, trade_date)`，写入 `data['industry_float_mv']`；main() 中在「行业指数」后调用，缺权限时置空列表。 |
| 2 | 同上 | 新增 `collect_industry_forecast_risk(pro, rate_limiter, report_period)`，依赖申万成分或 dim_stock，写入 `data['industry_forecast_risk']`。 |
| 3 | 同上 或 财务 ETL | 确定 Capex 来源；新增 `collect_industry_capex_yoy(ws 或 pro, ...)`，写入 `data['industry_capex_yoy']`。 |
| 4 | 同上 | 新增 `collect_real_estate_l2(pro, rate_limiter)`，写入 `data['real_estate_l2']`（可选）。 |
| 5 | 同上 | main() 中 data 初始化增加上述 4 个 key，默认 `[]`；各采集函数内部 try/except，失败不阻塞其他块。 |

## 五、规则引擎改造清单

| 步骤 | 文件 | 内容 |
|------|------|------|
| 1 | `industry_cycle_rule_engine.py` | 新增 `build_industry_float_mv_map(cycle_data)`；run_suggestions 中传入 `float_mv_亿`；suggest_cycle 中资金判下滑分支增加「流出/流通市值 ≥ 1%」条件与 reason。 |
| 2 | 同上 | 新增 `build_industry_forecast_risk_map(cycle_data)`；suggest_cycle 或 run_suggestions 后处理：对上升期且 pre_dec_pct 过高的行业追加 reason 或 `warning_forecast`。 |
| 3 | 同上 | 新增 `build_industry_capex_yoy_map(cycle_data)`；在成熟期分支中若 capex_yoy 明显为负则 reason 追加 Capex 说明。 |
| 4 | 同上 | 房地产分支：若存在 real_estate_l2，可输出子板块信息；或支持按二级行业配置单独规则（可选 B）。 |

## 六、配置与常量

- 在规则引擎或单独 config 中定义常量，便于调参：
  - `MONEY_OUTFLOW_ABS_DECLINING_亿 = 50`（现有）
  - `MONEY_OUTFLOW_RATIO_DECLINING = 0.01`（相对资金 1%）
  - `FORECAST_PRE_DEC_WARN_PCT = 0.3`（预减+略减等占比超 30% 提示）
  - `CAPEX_YOY_MATURE_THRESHOLD = -10`（Capex 同比低于 -10% 标成熟期特征）

## 七、实施阶段建议

| 阶段 | 内容 | 依赖 |
|------|------|------|
| **P0** | ① 相对资金：采集 industry_float_mv + 规则接入比例判下滑 | Tushare 5000 积分、sw_daily |
| **P1** | ② 业绩预告：采集 industry_forecast_risk + reason/warning 追加 | forecast/forecast_vip、申万成分 |
| **P2** | ③ Capex：确定数据源 → 采集 industry_capex_yoy → 成熟期 reason 增强 | cashflow、fact 或 ETL |
| **P3** | ④ 房地产子板块：采集 real_estate_l2 → 展示或二级规则 | index_classify、index_member_all |

每阶段完成后均可独立上线：新字段为空时规则自动退化为当前行为，不影响现有建议结果。

---

## 八、测试与回退

- **单测**：对 `build_industry_float_mv_map` 等用 fixture 的 cycle_data 片段做单元测试。
- **集成**：跑一次 `collect_industry_cycle_data.py` 生成带新字段的 cycle_data，再跑 `industry_cycle_update.py --mode suggest`，检查建议与 reason 是否符合预期。
- **回退**：新字段或新分支异常时，在采集层不写新 key 或规则层跳过新分支即可恢复原逻辑。

以上方案可直接按阶段拆分开发任务并在代码中实现；数据来源与接口细节以 [行业周期规则优化-数据来源.md](./行业周期规则优化-数据来源.md) 为准。
