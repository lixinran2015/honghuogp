## 二、主线雷达逻辑 (StartupMainlineRadar)

### 2.1 核心功能

主线雷达用于**按板块聚合启动信号**，识别当日市场的热点主线和次主线。

**数据来源：**
- `fact_stock_startup_candidate`：启动候选信号表
- `dim_stock`：股票基本信息（行业、名称）
- `fact_stock_sector`：股票所属板块（题材）
- `fact_sector_leader_snapshot`：板块龙头快照（4+2规则计算）

### 2.2 处理流程

```
步骤1: 取出窗口内启动候选信号（score≥min_score，stage为confirmed/started）
         │
步骤2: 查询每只股票的概念标签（fact_stock_sector + dim_sector）
         │
步骤3: 按行业/概念聚合统计（日信号数、活跃天数、平均得分）
         │
步骤4: 获取板块龙头角色（空间龙头/补涨/跟风）
         │       ├─ 优先从 rolling_30d_v2 窗口查询
         │       └─ 获取 leader_type, continuous_limit, period_return_pct, change_pct_5d
         │
步骤5: 生成板块强度分数 = 近3日信号数×2 + 不同股票数×0.5 + 趋势方向×1
         │
步骤6: 组装「接力链条」：为每个板块选出代表个股（最多6只）
         │       ├─ 按角色优先级排序（空间龙头 > 补涨龙 > 相对强势 > 跟风）
         │       └─ 近期走弱（5日涨幅≤0）的会被降级为"相对强势"
         │
步骤7: 补全无候选板块但有真实空间龙头的板块（避免遗漏高标龙头）
```

### 2.3 板块强度计算公式

```python
# 强度分数 = 近3日爆发程度 + 宽度 + 趋势方向
strength_score = recent_3d_signals * 2.0 + distinct_stock_count * 0.5 + trend * 1.0

# 趋势方向 = 近3日信号数 - 前3日信号数（升温为正，降温为负）
trend = recent_3d_signals - prev_3d_signals
```

### 2.4 接力角色映射规则

| leader_type | 近期强弱 | 角色 | 优先级 |
|------------|---------|------|--------|
| absolute_leader | 强（5日涨幅>0） | 空间龙头 | 400 + cl |
| absolute_leader | 弱（5日涨幅≤0） | 相对强势 | 200 + cl |
| catch_up | 强（5日涨幅>0） | 补涨龙 | 300 + cl |
| catch_up | 弱（5日涨幅≤0） | 相对强势 | 200 + cl |
| rel_strength/resilient | 任意 | 相对强势 | 200 + cl |
| follower | 任意 | 跟风 | 100 + cl |

**重要说明：**
- 近期走弱（5日涨幅≤0）的股票会被降级，不再显示为"空间龙头"或"补涨龙"
- 这确保了主线雷达展示的是**当前真正强势**的龙头，而非过期的历史龙头

## 三、4+2规则 (rolling_30d_v2)

### 3.1 规则概述

4+2规则是识别板块龙头的核心算法，存储在 `fact_sector_leader_snapshot` 表中，window_id = "rolling_30d_v2"。

### 3.2 4个核心指标

| 指标 | 说明 | 作用 |
|-----|------|------|
| ret_window | 窗口期（30日）涨幅 | 识别涨幅最大的股票 |
| continuous_limit | 最大连板数 | 衡量强度持续性 |
| avg_amount | 窗口期平均成交额 | 过滤流动性差的股票 |
| first_start_date | 首次启动日期 | 识别启动顺序 |

### 3.3 2个约束条件

| 约束 | 说明 |
|-----|------|
| recent_strength | 近期强弱：5日涨幅 > 0 |
| liquidity_ok | 流动性：平均成交额 ≥ 阈值 |

### 3.4 龙头角色识别

```python
# 在板块内部按综合评分排序
# 综合评分 = 涨幅归一化 × 0.4 + 成交额归一化 × 0.3 + 市值归一化 × 0.3

# 龙头类型判定：
absolute_leader  # 综合评分最高 + 近期走强
rel_strength     # 板块普跌时，跌幅最小的（相对抗跌）
catch_up         # 涨幅次高 + 成交额放大明显（补涨）
resilient        # 普跌板块中的抗跌代表
follower         # 其他有涨幅的股票
```

## 四、龙头跟踪逻辑 (LeaderTracking)

### 4.1 核心功能

龙头跟踪池用于**持久化存储**被识别为"空间龙头"或"刚启动龙头"的股票，支持：
- 历史龙头保留（时效性过滤：21天过期）
- 退潮/强势状态检测
- AI智能评分与买点识别

### 4.2 数据表结构

**fact_leader_tracking_pool（跟踪池主表）：**

| 字段 | 说明 |
|-----|------|
| ts_code | 股票代码 |
| name | 股票名称 |
| is_space | 是否空间龙头 |
| is_new | 是否刚启动龙头 |
| first_space_date | 首次成为空间龙头日期 |
| first_new_date | 首次成为刚启动日期 |
| last_seen_date | 最近出现日期 |
| sectors | 所属板块列表 |
| continuous_limit | 历史最大连板数 |
| score | AI评分分数 |
| grade | AI评分等级 |
| buy_signal | 买点信号 |

### 4.3 入池条件

**空间龙头入池：**
- 来自主线雷达的 `space_leaders_lead` 列表
- leader_type = "absolute_leader" 且 近期走强

**刚启动龙头入池：**
- 来自主线雷达的接力链条
- 满足以下条件：
  ```python
  leader_type in ("absolute_leader", "catch_up")  # 空间龙头或补涨
  continuous_limit <= 3                           # 连板不超过3板
  15% <= period_return_pct <= 120%                # 30日涨幅在合理区间
  ```

### 4.4 时效性过滤

```python
# 超过15个交易日（约21自然日）未出现的视为归档
cutoff = trade_date - timedelta(days=21)
# 只保留 last_seen_date >= cutoff 的股票
```

### 4.5 实时状态覆盖

跟踪池持久化的 `is_space/is_new` 可能过期，查询时会用当日主线雷达结果实时覆盖：

```python
# 1. 从持久化表读取基础数据
pool_list = 查询 fact_leader_tracking_pool

# 2. 获取当日实时状态
analyzer_result = 调用主线雷达分析（当日数据）
current_state_map = 构建当日状态映射

# 3. 用实时状态覆盖过期数据
for item in pool_list:
    if item.ts_code in current_state_map:
        item.is_space = current_state_map[item.ts_code].is_space
        item.is_new = current_state_map[item.ts_code].is_new
    else:
        # 当日不在雷达中：清空活跃角色标记
        item.is_space = False
        item.is_new = False

# 4. 过滤：只保留 is_space 或 is_new 为 True 的股票
filtered_pool = [item for item in pool_list if item.get("is_space") or item.get("is_new")]
```

## 五、退潮判定逻辑

### 5.1 退潮信号指标

退潮判定基于4个加权信号：

| 信号 | 权重 | 说明 |
|-----|------|------|
| deep_drawdown | 0.35 | 深度回调：从近期高点回撤超过8% |
| break_ma20_persist | 0.30 | 持续跌破MA20：连续2日收盘价低于MA20 |
| volume_price_divergence | 0.20 | 量价背离：价格微涨/平但成交量萎缩超过20% |
| shrink_volume_down | 0.15 | 缩量下跌：价格下跌且成交量萎缩 |

### 5.2 退潮等级计算

```python
# 退潮分数 = Σ(信号触发 × 权重)
retreat_score = (
    deep_drawdown * 0.35 +
    break_ma20_persist * 0.30 +
    volume_price_divergence * 0.20 +
    shrink_volume_down * 0.15
)

# 退潮等级判定：
if retreat_score >= 0.5:
    retreat_label = "退潮风险"  # 建议卖出
elif retreat_score >= 0.3:
    retreat_label = "震荡"      # 观望
else:
    retreat_label = "强势"      # 可持有
```

### 5.3 与AI评分的关系

**重要：有退潮风险的股票会被排除在AI评分之外**

```python
# 在 UnifiedShortTermScorer.batch_score() 中：
for stock in pool:
    stats = compute_retreat_stats_at_end_date(session, ts_code, trade_date)
    if stats and stats.get("retreat_label") == "退潮风险":
        logger.info(f"AI评分：跳过退潮风险股票 {ts_code}")
        continue  # 跳过该股票，不参与评分
```

## 六、连板数 (continuous_limit) 的两种含义

### 6.1 历史最大连板数

存储在 `fact_leader_tracking_pool.continuous_limit` 中：
- 表示该股在窗口期内的**历史最大**连续涨停天数
- 用于识别该股的龙头地位强度

### 6.2 当前连板数

在 `fact_sector_leader_snapshot` 中：
- 表示计算时点该股的**当前**连续涨停天数
- 每日重新计算，反映最新状态

### 6.3 前端展示

龙头跟踪页面展示的是**当前连板数**（从当日主线雷达结果获取），而非历史最大连板数。

## 七、数据同步机制

### 7.1 同步流程

```
┌─────────────────────────────────────────────────────────┐
│ 每日首次访问龙头跟踪页面时触发同步                        │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 检查 sync_log：该交易日是否已同步？                       │
└─────────────────────────────────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              │                           │
              ▼ 未同步                     ▼ 已同步
┌───────────────────────┐      ┌───────────────────────┐
│ 调用主线雷达分析当日数据 │      │ 直接返回已同步数据     │
│ 识别新的空间/刚启动龙头  │      │                       │
└───────────────────────┘      └───────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 增量写入 fact_leader_tracking_pool：                     │
│ - 新股票：插入新记录                                      │
│ - 已存在：更新 is_space/is_new/last_seen_date/sectors   │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 写入 sync_log 标记该交易日已同步                          │
└─────────────────────────────────────────────────────────┘
```

### 7.2 Bootstrap机制

首次部署或跟踪池为空时，自动从最近N日历史数据初始化：

```python
# 默认回溯180天
bootstrap_days = 180
start_dt = trade_date - timedelta(days=bootstrap_days)

# 调用主线雷达分析历史窗口
result = analyzer.analyze(start_date=start_dt, end_date=trade_date)

# 将历史空间/刚启动龙头写入跟踪池
```

### 7.3 追补机制

若中间若干交易日从未调用过get_pool，sync_log会缺档。每次拉池时自动补跑：

```python
# 检查最近30个交易日是否有未同步的日期
missing_dates = [d for d in last_30_trade_dates if d not in synced_dates]

# 每请求最多补跑30个缺失日期（避免超时）
for td in missing_dates[:30]:
    sync_for_trade_date(td)
```

## 八、常见问题排查

### 8.1 过期龙头仍显示

**症状：** 某股票（如东百集团、韶能股份）已经走弱，但仍出现在龙头跟踪列表

**排查步骤：**
1. 检查 `fact_sector_leader_snapshot` 中该股票的 leader_type 和 change_pct_5d
2. 确认主线雷达是否正确降级（5日涨幅≤0的股票会被降级为"相对强势"）
3. 检查 `fact_leader_tracking_pool` 中的 `last_seen_date` 是否过期（21天）
4. 确认 `is_space` 和 `is_new` 在当日实时覆盖后是否为 False

**修复措施：**
- 时效性过滤会自动清理21天未出现的股票
- 实时状态覆盖会将过期的 is_space/is_new 标记为 False

### 8.2 显示的历史连板数不正确

**症状：** 某股票显示"4板"，但当前已不再是4板状态

**原因：** 早期实现使用历史最大连板数而非当前连板数

**修复：** 现在从 `fact_sector_leader_snapshot` 获取当前连板数，而非历史最大连板数

### 8.3 退潮风险股票仍参与AI评分

**症状：** 有退潮风险的股票仍被AI评分并推荐

**修复：** `UnifiedShortTermScorer.batch_score()` 现在会过滤掉退潮风险股票

## 十、总结

### 主线雷达 vs 龙头跟踪

| 维度 | 主线雷达 | 龙头跟踪 |
|-----|---------|---------|
| 目的 | 发现当日热点主线 | 监控历史龙头状态 |
| 数据保留 | 不保留（当日分析） | 持久化（21天过期） |
| 展示内容 | 板块强度+接力链条 | 日线走势+退潮状态+AI评分 |
| 角色判定 | 基于4+2规则 | 继承主线雷达结果 |
| 时效性 | 只反映当日 | 支持历史回溯 |

### 数据依赖关系

```
fact_sector_leader_snapshot (4+2规则识别龙头)
           │
           ▼
fact_stock_startup_candidate (启动信号)
           │
           ▼
StartupSectorAnalyzer (主线雷达聚合分析)
           │
           ▼
fact_leader_tracking_pool (龙头跟踪池持久化)
           │
           ▼
LeaderTrackingView (前端展示+AI评分)
```

### 关键设计决策

1. **使用 rolling_30d_v2 而非 current_rolling_30d**：新规则更准确，考虑了近期强弱
2. **近期走弱股票降级**：5日涨幅≤0的不再显示为空间龙头/补涨龙
3. **退潮风险股票排除AI评分**：避免买入正在退潮的股票
4. **21天时效性过滤**：自动清理过期龙头
5. **实时状态覆盖**：查询时用当日主线雷达结果覆盖过期数据
