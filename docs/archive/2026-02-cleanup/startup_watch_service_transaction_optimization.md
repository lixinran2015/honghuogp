# 事务管理优化说明

## 优化内容

### 1. 批量提交机制

**问题：**
- 之前所有股票的检查在一个大事务中提交
- 事务时间过长，导致数据库锁等待
- 部分股票失败会影响全部股票的更新

**解决方案：**
- 实现批量提交：每 `BATCH_COMMIT_SIZE`（默认10）只股票提交一次
- 减少事务时间，降低数据库锁等待
- 单个批次失败不影响其他批次

### 2. Savepoint 隔离机制

**问题：**
- 单个股票检查失败时，可能影响其他股票

**解决方案：**
- 使用 SQLAlchemy 的 `begin_nested()` 创建 savepoint（嵌套事务）
- 每个股票的操作在独立的 savepoint 中
- 单个股票失败时，只回滚该股票的 savepoint，不影响其他股票

### 3. 兼容性处理

**问题：**
- 某些数据库可能不支持 savepoint

**解决方案：**
- 自动检测数据库是否支持 savepoint
- 如果不支持，回退到批量提交模式
- 在批量提交模式下，单个股票失败只影响当前批次

## 代码变更

### 新增常量

```python
BATCH_COMMIT_SIZE = 10  # 批量提交大小
```

### 新增方法

```python
def _check_savepoint_support(self, session) -> bool:
    """检查数据库是否支持 savepoint"""
```

### 优化后的流程

```
1. 检测数据库是否支持 savepoint
2. 对每只股票：
   a. 如果支持 savepoint，创建独立的 savepoint
   b. 检查股票
   c. 提交 savepoint（该股票的操作）
   d. 每 N 只股票提交一次主事务
3. 如果股票检查失败：
   a. 如果支持 savepoint，只回滚该股票的 savepoint
   b. 如果不支持，回滚当前批次
4. 最后提交剩余的更新
```

## 性能提升

### 之前
- 事务时间：所有股票检查完成后才提交（可能几分钟）
- 锁等待：长时间持有数据库锁
- 失败影响：单个失败影响全部

### 优化后
- 事务时间：每10只股票提交一次（约几秒）
- 锁等待：大幅减少
- 失败影响：单个失败只影响当前批次或该股票

## 使用建议

### 调整批量提交大小

根据实际情况调整 `BATCH_COMMIT_SIZE`：

```python
# 如果股票数量少（<50），可以设置较小值
BATCH_COMMIT_SIZE = 5

# 如果股票数量多（>100），可以设置较大值
BATCH_COMMIT_SIZE = 20
```

### 监控指标

建议监控以下指标：
- 批量提交耗时
- 提交失败率
- 单个股票检查失败率

## 注意事项

1. **Savepoint 支持：** 大多数数据库（PostgreSQL、MySQL InnoDB）都支持 savepoint，但某些数据库可能不支持
2. **回滚范围：** 如果不支持 savepoint，单个股票失败会回滚当前批次，可能影响当前批次的其他股票
3. **最终提交：** 确保最后提交剩余的更新，避免数据丢失

## 测试建议

1. **正常流程测试：** 验证批量提交正常工作
2. **异常流程测试：** 验证单个股票失败不影响其他股票
3. **性能测试：** 对比优化前后的性能指标
4. **并发测试：** 验证并发场景下的正确性
