# S3策略数据缺失与策略调整分析

## 📊 当前S3配置

```python
S3_FILTER_CONFIG = {
    'min_turnover_rate': 0.1,  # 临时降级：0.1%
    'require_limit_up': False,  # 临时不要求
    'min_change_pct': 0.0,  # 临时降级：0%
}
```

## 📋 S3策略目标

**目标**：次新、妖股、事件驱动

**理想过滤条件**：
1. 换手率 > 5%（高活跃度）
2. 连续涨停 > 1天 OR 今日涨停（情绪驱动）
3. 涨幅 > 3%（短期强势）

## 📊 当前数据状态

### ✅ 有数据的字段
- **换手率(turnover_rate)**: ✅ 完整（5150只有数据，99.7%）
- **涨跌幅(pct_chg/change_pct)**: ✅ 完整（基本完整）

### ❌ 缺失的字段
- **limit_up_days** (连续涨停天数): ❌ 字段不存在
- **is_today_limit_up** (今日是否涨停): ❌ 字段不存在
- **fact_limit_up_daily表**: ⚠️ 需要检查数据完整性

## 🔍 当前过滤结果

- **基础池**: 1372 只
- **S3过滤后**: 627 只
- **过滤逻辑**: 
  - 换手率 >= 0.1%: 1366 只满足
  - 涨幅 >= 0%: 全部满足（因为min_change_pct=0）
  - **最终**: 627 只（可能是其他条件或数据问题）

## ⚠️ 问题分析

### 问题1: 配置过于宽松
- `min_turnover_rate`: 0.1%（太宽松，几乎不过滤）
- `min_change_pct`: 0%（不过滤涨幅）
- `require_limit_up`: False（不要求涨停）

**影响**: S3策略失去了"情绪/事件驱动"的特性，变成了一个宽松的基础池。

### 问题2: 涨停数据缺失
- `fact_limit_up_daily`表可能没有数据
- 无法判断连续涨停天数
- 无法判断今日是否涨停

**影响**: 无法实现"连续涨停 > 1天 OR 今日涨停"的过滤条件。

## ✅ 建议方案

### 方案1: 提高过滤标准（推荐）

**短期调整**（数据补齐前）:
```python
S3_FILTER_CONFIG = {
    'min_turnover_rate': 3.0,  # 提高到3%（活跃度要求）
    'require_limit_up': False,  # 暂时不要求
    'min_change_pct': 3.0,  # 要求涨幅 >= 3%（短期强势）
}
```

**长期目标**（数据补齐后）:
```python
S3_FILTER_CONFIG = {
    'min_turnover_rate': 5.0,  # 5%（高活跃度）
    'require_limit_up': True,  # 要求涨停
    'min_change_pct': 0.0,  # 如果要求涨停，涨幅条件可放宽
}
```

### 方案2: 补齐涨停数据

**需要补充的数据**:
1. `fact_limit_up_daily`表数据
   - `continuous_days` (连续涨停天数)
   - `is_today_limit_up` (今日是否涨停)
   - `seal_amount` (封板金额)
   - `first_limit_time` (首次涨停时间)

2. 数据来源:
   - 东财API: `https://push2.eastmoney.com/api/qt/clist/get?fs=m:0+cp:1`
   - 或使用涨停板专用接口

### 方案3: 使用涨幅替代涨停（临时）

**当前实现**: 使用`pct_chg >= 9.5%`判断涨停

**优点**: 不需要额外的涨停数据表

**缺点**: 可能误判（停牌复牌等特殊情况）
