**版本**: v1.0  
**日期**: 2026-04-13  
**作者**: Claude / 项目维护者  
**状态**: 待实施

---

## 1. 设计目标

将现有「短线龙头智能跟踪系统」从个人研究项目发展为面向散户投资者的可持续商业化产品。核心策略为：

> **先以内容输出验证付费需求，再逐步部署 SaaS 数据工具，最终形成订阅制商业模式。**

### 关键约束

- **资源约束**：个人副业，每周 5-10 小时投入，预算极低。
- **合规约束**：当前无公司主体、无证券投资咨询牌照，所有对外输出必须严格限定在「数据展示/个人研究记录」范畴。
- **技术约束**：优先复用现有 FastAPI + Vue 3 + PostgreSQL 技术栈，新开发工作量最小化。

---

## 2. 成功标准

3 个月验收指标：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 内容发布连续性 | ≥ 20 天 | 每日龙头日报不间断 |
| 公域粉丝/关注数 | ≥ 200（公众号）或 ≥ 300（小红书） | 验证内容吸引力 |
| 付费转化人数 | ≥ 5 人 | 任意金额，验证付费意愿 |
| Demo 站点日均 UV | ≥ 30 | 若进入第二阶段 |
| 种子用户群人数 | ≥ 50 | 若进入第二阶段 |
| Go/No-Go 决策 | 明确 | 第 12 周前完成 |

## 3. 产品化路径

### 3.1 阶段一：内容验证期（第 1-4 周）

**目标**：通过零开发成本的每日内容输出，快速验证散户对短线龙头信息的付费意愿。

#### 3.1.1 内容形态：「A股短线龙头日报」

每晚固定时间发布，包含以下模块：

1. **情绪周期判断**：基于涨跌停数据、连板高度、市场宽度输出当日情绪周期（冰点/低迷/震荡/退潮/高涨）。
2. **Top 5 空间龙头**：列出当日系统识别的空间龙头，附带 LSTM-MAB 评分等级（S/A/B）。
3. **买点信号池**：列出当日触发技术形态信号的 2-3 只个股，只展示评分数据和因子得分，不给出买卖建议。
4. **次日跟踪名单**：基于现有跟踪池数据，列出次日值得观察的个股清单。

#### 3.1.2 发布平台

- **主阵地**：微信公众号（承载深度内容、私域引流）。
- **引流阵地**：小红书（发布图表、数据可视化截图，引流至公众号）。

#### 3.1.3 私域漏斗

- **免费层**：关注公众号，每晚获取日报推送。
- **付费层**：9.9-19.9 元/月的微信群或知识星球，次日早盘前获得数据截图/简版推送。

#### 3.1.4 合规要求

- 每篇内容底部固定附加免责声明：
  > "本内容仅为数据整理与个人研究记录，不构成任何投资建议。股市有风险，入市需谨慎。"
- 不出现「推荐买入」「目标价」「必涨」「仓位建议」等强投顾话术。
- 买卖点信号统一用中性表述：「技术形态触发」「资金流向异常」「情绪热度较高」。

#### 3.1.5 同步技术准备

- 将现有 FastAPI + Vue 系统部署到个人可远程访问的服务器（推荐阿里云轻量应用服务器 99 元/年套餐）。
- 编写每日数据导出脚本（Python），自动将龙头池、情绪周期、买点信号生成 Markdown 或图片格式，减少人工整理时间。

---

### 3.2 阶段二：MVP 公测期（第 5-8 周）

**目标**：上线一个极简公开 Demo，让种子用户自助查看数据，收集真实反馈并筛选高意愿用户。

#### 3.2.1 Demo 形态

- **前端**：直接复用现有 Vue 3 项目，打包后部署到 Vercel/Netlify（免费 CDN）。
- **后端数据**：采用「静态 JSON + 定时更新」方案。每日收盘后跑批生成 JSON 文件，上传至 Cloudflare R2 或阿里云 OSS（低流量场景几乎免费）。前端直接读取静态 JSON，不暴露复杂 API。

#### 3.2.2 功能裁剪

| 现有功能 | Demo 处理方式 |
|----------|---------------|
| 龙头池列表 + 评分 | **保留** |
| 情绪周期看板 | **保留** |
| 历史回测曲线 | **保留** |
| 买卖点信号文字 | **隐藏或弱化** |
| 仓位建议 | **隐藏** |
| 止损止盈提示 | **隐藏** |

所有面向用户的功能文案统一做「去投顾化」处理：

- 「买入信号」→ 「技术形态触发」
- 「卖出信号」→ 「风险指标提示」
- 「仓位建议」→ 「市场热度参考」

#### 3.2.3 用户反馈收集

- Demo 站点底部固定放置二维码/链接，引导用户加入「种子用户反馈群」。
- 每周在群内进行 1 次简短调研：你最关心的数据维度？你愿意为实时数据/高级筛选付多少钱？

#### 3.2.4 用户系统（可选）

若希望收集用户邮箱或控制访问权限，可直接接入 Clerk/Auth0 免费版，不自建用户系统。

---

### 3.3 阶段三：SaaS 预备期（第 9-12 周）

**目标**：基于前两个阶段的数据，做出明确的商业化 Go/No-Go 决策。

#### 3.3.1 决策标准

**Go 条件（满足任意一条即可）**：
- 付费转化人数 ≥ 20 人；
- Demo 用户调研中 ≥ 30% 表示愿意月付 30 元以上；
- 有持牌机构主动联系合作。

**No-Go 动作**：
- 继续以内容/社群形式轻运营；
- 暂不投入 SaaS 订阅系统开发；
- 继续积累粉丝和数据案例，等待时机。

#### 3.3.2 Go 后行动清单

1. **公司注册**：注册科技公司或信息咨询公司。
2. **牌照路径**：调研证券投资咨询牌照申请条件，或寻找持牌机构挂靠合作。
3. **订阅方案设计**：
   - **免费版**：T+1 延迟数据、基础龙头池查看、情绪周期历史。
   - **Pro 版（29-49 元/月）**：T 日收盘后实时数据、高级筛选、自定义跟踪列表、回测参数调整。
4. **技术升级**：
   - 用户系统：使用 Supabase/Firebase（低成本、快速上线）。
   - 支付系统：申请微信支付小微商户或支付宝个人开发者账户。
   - 权限控制：后端增加基于订阅级别的 API 鉴权（基础版限制数据时效和调用频次）。

## 4. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| **合规风险** | 高 | 所有对外内容严格限定为「数据展示/个人研究」，不使用投资顾问话术，固定免责声明，隐藏仓位建议与买卖点文字。 |
| **时间不足** | 中 | 第一阶段核心动作「每日 20 分钟产出内容」，技术工作压缩到周末，不追求完美，先完成再优化。 |
| **数据可靠性争议** | 中 | 不在内容中过度宣传胜率/收益，公开分享的数据均加免责声明。系统持续跑实盘跟踪，积累真实案例。 |
| **竞争同质化** | 低 | 差异化壁垒在于「LSTM-MAB 评分 + 情绪周期 + 买卖点」的完整量化闭环，市场上多数博主停留在主观复盘层面。 |

## 6. 关键里程碑时间线

```
Week 1-2  ━━ 部署远程环境 + 确定日报模板 + 开始发布内容
Week 3-4  ━━ 持续内容输出 + 建立免费/付费私域漏斗
Week 5-6  ━━ 上线公开 Demo + 招募种子用户群
Week 7-8  ━━ 收集反馈 + 优化 Demo 功能与文案
Week 9-10 ━━ 评估数据 + 做出 Go/No-Go 决策
Week 11-12━━ 若 Go：注册公司 + 确定牌照路径 + SaaS 技术方案文档化
```
