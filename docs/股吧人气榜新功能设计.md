# 股吧人气榜新功能设计

## 功能需求

1. **第一次入榜单识别**：识别哪些股票是第一次进入榜单
2. **持续榜单天数**：计算每个股票连续在榜单中的天数

## 实现方案

### 1. 第一次入榜单识别

#### 后端实现
- **API端点**：`GET /api/guba/popularity/first-entry`
- **功能**：查询指定日期（默认最新日期）的榜单中，哪些股票是第一次进入榜单
- **实现逻辑**：
  1. 获取指定日期的榜单数据
  2. 对于榜单中的每个股票，查询其在数据库中最早出现的日期
  3. 如果最早出现日期等于查询日期，则标记为"第一次入榜单"
  4. 返回结果包含：股票代码、股票名称、当前排名、首次入榜日期

#### 前端实现
- 在排行榜表格中增加"首次入榜"列
- 如果是第一次入榜，显示"新"标签或高亮显示
- 可以添加筛选功能，只显示第一次入榜的股票

### 2. 持续榜单天数

#### 后端实现
- **API端点**：`GET /api/guba/popularity/continuous-days`
- **功能**：计算每个股票连续在榜单中的天数
- **实现逻辑**：
  1. 获取指定日期（默认最新日期）的榜单数据
  2. 对于榜单中的每个股票：
     - 从查询日期往前查找，计算连续出现在榜单中的天数
     - 如果某一天不在榜单中，则停止计算
  3. 返回结果包含：股票代码、股票名称、当前排名、持续天数

#### 前端实现
- 在排行榜表格中增加"持续天数"列
- 可以按持续天数排序
- 可以添加筛选功能，例如只显示持续3天以上的股票

## 数据库查询优化

### 第一次入榜单查询
```sql
-- 查询每个股票最早出现的日期
SELECT ts_code, MIN(crawl_date) as first_entry_date
FROM fact_guba_popularity_rank
GROUP BY ts_code;

-- 查询指定日期第一次入榜的股票
SELECT r1.ts_code, r1.stock_name, r1.rank_position, r1.crawl_date
FROM fact_guba_popularity_rank r1
INNER JOIN (
    SELECT ts_code, MIN(crawl_date) as first_entry_date
    FROM fact_guba_popularity_rank
    GROUP BY ts_code
) r2 ON r1.ts_code = r2.ts_code AND r1.crawl_date = r2.first_entry_date
WHERE r1.crawl_date = :query_date;
```

## 前端UI设计

### 表格列增加
1. **首次入榜**列：
   - 如果是第一次入榜，显示"新"标签（绿色背景）
   - 显示首次入榜日期（鼠标悬停显示）

2. **持续天数**列：
   - 显示连续在榜天数
   - 可以按此列排序
   - 不同天数用不同颜色标识（例如：1-3天黄色，4-7天橙色，8天以上红色）

### 筛选功能
- 添加筛选器：
  - "仅显示首次入榜"
  - "持续天数 ≥ N天"

### 排序功能
- 可以按持续天数排序（升序/降序）

## 性能考虑

1. **缓存机制**：第一次入榜和持续天数的计算结果可以缓存，因为历史数据不会变化
2. **索引优化**：确保 `(ts_code, crawl_date)` 有索引，提高查询效率
3. **批量查询**：对于持续天数计算，可以批量查询多个股票，减少数据库查询次数
