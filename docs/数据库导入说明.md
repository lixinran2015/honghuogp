# 📥 数据库备份导入说明

## 📍 备份文件位置

备份文件：`database_backup.sql`

## 🚀 导入方法

### 方法1: 使用批处理脚本（推荐，Windows）

```powershell
.\import_database.bat
```

脚本会自动：
- 检查备份文件是否存在
- 读取数据库配置
- 提示确认（因为会覆盖现有数据）
- 执行导入

### 方法2: 使用 psql 命令行

#### Windows PowerShell

```powershell
# 设置密码环境变量（避免交互式输入）
$env:PGPASSWORD = "qazwsx"

# 导入数据库
psql -U postgres -h localhost -p 5432 -d quantitative_trading -f database_backup.sql

# 清除密码（安全）
Remove-Item Env:PGPASSWORD
```

#### Windows 命令提示符（CMD）

```cmd
set PGPASSWORD=qazwsx
psql -U postgres -h localhost -p 5432 -d quantitative_trading -f database_backup.sql
set PGPASSWORD=
```

#### 如果 psql 不在 PATH 中

使用完整路径：

```powershell
# PowerShell
$env:PGPASSWORD = "qazwsx"
"C:\Program Files\PostgreSQL\14\bin\psql.exe" -U postgres -h localhost -p 5432 -d quantitative_trading -f database_backup.sql
Remove-Item Env:PGPASSWORD
```

```cmd
REM CMD
set PGPASSWORD=qazwsx
"C:\Program Files\PostgreSQL\14\bin\psql.exe" -U postgres -h localhost -p 5432 -d quantitative_trading -f database_backup.sql
set PGPASSWORD=
```

### 方法3: 使用 pgAdmin（图形界面）

1. 打开 **pgAdmin 4**
2. 连接到 PostgreSQL 服务器
3. 展开 **Servers** → **PostgreSQL 14** → **Databases**
4. 右键点击 **quantitative_trading** 数据库
5. 选择 **Restore...**
6. 在 **Filename** 中选择 `database_backup.sql` 文件
7. 点击 **Restore** 按钮

**注意**: pgAdmin 通常需要 `.backup` 或 `.dump` 格式，如果是 `.sql` 文件，可能需要使用 **Query Tool** 执行。

### 方法4: 使用 Python 脚本

```python
import subprocess
import os
from data_warehouse.config import DB_USER, DB_PASSWORD, DB_HOST, DB_PORT, DB_NAME

# 设置环境变量
os.environ['PGPASSWORD'] = DB_PASSWORD

# 执行导入
cmd = [
    'psql',
    '-U', DB_USER,
    '-h', DB_HOST,
    '-p', str(DB_PORT),
    '-d', DB_NAME,
    '-f', 'database_backup.sql'
]

result = subprocess.run(cmd, capture_output=True, text=True)

if result.returncode == 0:
    print('✅ 导入成功！')
else:
    print('❌ 导入失败：')
    print(result.stderr)

# 清除密码
del os.environ['PGPASSWORD']
```

## 📝 命令参数说明

```
psql [选项] -f 备份文件.sql

常用选项：
  -U, --username=用户名     数据库用户名（默认：postgres）
  -h, --host=主机           数据库主机（默认：localhost）
  -p, --port=端口           数据库端口（默认：5432）
  -d, --dbname=数据库名     目标数据库名称
  -f, --file=文件           要执行的SQL文件
  -W, --password            提示输入密码
```

## ⚠️ 重要提示

### 1. 备份会覆盖现有数据

导入备份文件会**覆盖**数据库中现有的所有数据！

**建议**：
- 如果数据库中有重要数据，先备份现有数据
- 确认备份文件是最新的
- 在测试环境先验证

### 2. 确保数据库已创建

导入前确保数据库已存在：

```powershell
# 如果数据库不存在，先创建
psql -U postgres -c "CREATE DATABASE quantitative_trading;"
```

### 3. 大文件导入

如果备份文件很大（>100MB），导入可能需要较长时间：

```powershell
# 显示导入进度（PostgreSQL 14+）
psql -U postgres -d quantitative_trading -f database_backup.sql --echo-all
```

### 4. 权限问题

确保数据库用户有足够的权限：

```sql
-- 在psql中执行
GRANT ALL PRIVILEGES ON DATABASE quantitative_trading TO postgres;
```

## ⚠️ 常见问题

### 问题1: 找不到 psql 命令

**错误**: `'psql' 不是内部或外部命令`

**解决**:
1. 使用完整路径：`"C:\Program Files\PostgreSQL\14\bin\psql.exe"`
2. 或添加到PATH环境变量

### 问题2: 密码认证失败

**错误**: `password authentication failed`

**解决**:
1. 检查密码是否正确
2. 使用 `PGPASSWORD` 环境变量设置密码
3. 或使用 `-W` 参数交互式输入密码

### 问题3: 数据库不存在

**错误**: `database "quantitative_trading" does not exist`

**解决**:
```powershell
psql -U postgres -c "CREATE DATABASE quantitative_trading;"
```

### 问题4: 权限不足

**错误**: `permission denied`

**解决**:
```sql
-- 以postgres用户连接
psql -U postgres

-- 授予权限
GRANT ALL PRIVILEGES ON DATABASE quantitative_trading TO postgres;
ALTER DATABASE quantitative_trading OWNER TO postgres;
```

### 问题5: 导入时间过长

**解决**:
- 大文件导入需要时间，请耐心等待
- 可以查看PostgreSQL日志了解进度
- 使用 `--echo-all` 参数查看执行过程

### 问题6: 字符编码问题

**错误**: `invalid byte sequence`

**解决**:
```powershell
# 指定编码
psql -U postgres -d quantitative_trading -f database_backup.sql --set=client_encoding=UTF8
```


4. **验证导入**
   ```powershell
   psql -U postgres -d quantitative_trading -c "SELECT COUNT(*) FROM dim_stock;"
   ```

## 💡 提示

1. **备份现有数据**：导入前建议先备份现有数据库
2. **使用事务**：PostgreSQL默认在事务中执行，如果出错会自动回滚
3. **查看日志**：导入过程中的错误会显示在终端
4. **分批导入**：如果文件太大，可以考虑分批导入
