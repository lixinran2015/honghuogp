# 行业周期规则优化 — 数据来源说明

以下四项为规则引擎「局限与优化方向」中提到的增强项，对应可获取数据的来源与接口（以项目已使用的 **Tushare** 为主）。

---

## 1. 相对资金：资金净流出 / 行业流通市值

**目标**：用「净流出占行业流通市值比例」替代绝对值 50 亿，使不同体量行业可比。

| 项目 | 说明 |
|------|------|
| **数据** | 申万行业维度**流通市值**（或总市值），按日 |
| **来源** | **Tushare**：`sw_daily`（申万行业日线行情） |
| **接口** | `pro.sw_daily(trade_date='YYYYMMDD', fields='ts_code,name,float_mv,total_mv')` |
| **字段** | `float_mv`：流通市值（**万元**）；`total_mv`：总市值（万元）。指数代码 `ts_code` 即申万行业指数（如 801010.SI 农林牧渔） |
| **文档** | https://tushare.pro/document/2?doc_id=327 |
| **积分** | 5000 积分 |
| **落地思路** | 采集时按交易日期拉取当日各申万一级行业 `float_mv`，写入 cycle_data 或单独 JSON；规则引擎中算「资金净流出(亿) / (float_mv/10000)」得到比例，再设阈值（如 >1%）判下滑。 |

---

## 2. 业绩预告 / PMI 等前瞻指标

**目标**：弥补财报营收滞后，用业绩预告、PMI 等做风险或景气修正。

| 项目 | 说明 |
|------|------|
| **业绩预告** | **Tushare**：`forecast`（业绩预告）、`express`（业绩快报） |
| **forecast** | `pro.forecast(ann_date=..., period=..., fields='ts_code,ann_date,type,p_change_min,p_change_max,change_reason')`，按公告日/报告期取；`type` 为预增/预减/扭亏/首亏等。全市场某期需 `forecast_vip`（5000 积分） |
| **express** | 业绩快报，口径比预告更接近正式报表。项目内已有 `self.pro.express` 调用（见 tushare_service） |
| **文档** | 业绩预告 https://tushare.pro/document/2?doc_id=45 ；业绩快报见站内「业绩快报」 |
| **积分** | forecast 2000；forecast_vip 5000 |
| **PMI** | **Tushare**：`cn_pmi`（中国 PMI）。项目已在 `collect_industry_cycle_data.collect_macro()` 中采集，写入 cycle_data 的 `macro.pmi`，可用于宏观景气过滤或提示。 |
| **落地思路** | 按报告期汇总「某申万行业下成分股」的业绩预告类型（预减/首亏占比等），作为该行业的风险信号；或仅做预警标签，不强制改周期。PMI 可与宏观区间结合（如 PMI<50 时对部分行业收紧上升期判定）。 |

---

## 3. 成熟期 + 资本开支（Capex）

**目标**：用资本开支下降等特征辅助定义成熟期（扩产放缓、更重视分红与现金流）。

| 项目 | 说明 |
|------|------|
| **数据** | 单股「购建固定资产、无形资产和其他长期资产支付的现金」（即常见 Capex 口径） |
| **来源** | **Tushare**：现金流量表 `cashflow` |
| **接口** | `pro.cashflow(ts_code=..., period=..., fields='ts_code,end_date,c_pay_acq_const_fiolta')` |
| **字段** | `c_pay_acq_const_fiolta`：购建固定资产、无形资产和其他长期资产支付的现金（单位：元） |
| **文档** | https://tushare.pro/document/2?doc_id=44 |
| **积分** | 2000；全市场批量用 `cashflow_vip` 5000 积分 |
| **落地思路** | 在 fact_fundamental 或单独表中增加 capex 字段（或从现有 ETL 的 cashflow 表取）；采集时按申万行业聚合（如中位数、同比变化），写入 cycle_data；规则中对「营收 0~10%」的行业，若 Capex 同比明显下降，可加强成熟期判定或单独标注「成熟期（Capex 下行）」。 |

---

## 4. 房地产子板块（保障房、商管等）

**目标**：房地产一级行业下再分二级/三级，对保障房、商管等子板块单独规则，而非一刀切下滑期。

| 项目 | 说明 |
|------|------|
| **数据** | 申万**二级/三级行业**分类及成分股 |
| **来源** | **Tushare**：`index_classify` + `index_member_all` |
| **index_classify** | `pro.index_classify(level='L2', src='SW')` 或 `level='L3'`，获取申万二级、三级行业列表（含 code、name）。房地产一级下会有多个二级（如房地产开发Ⅱ、房地产服务Ⅱ等），再下分三级。 |
| **index_member_all** | 已在使用。可按 `l2_code='801181.SI'` 或 `l3_code='...'` 拉取该二级/三级行业成分股；或按 `ts_code` 反查股票所属二级/三级。 |
| **文档** | 申万分类 https://tushare.pro/document/2?doc_id=181 ；成分 doc_id=335 |
| **积分** | 2000 |
| **落地思路** | 1）从 index_classify 筛出「房地产」下的 L2/L3 列表；2）为 dim_stock 或行业周期配置增加「申万二级/三级」字段（或单独映射表）；3）规则引擎中对「房地产」一级做分支：若可解析到二级（如房地产服务、保障房相关三级），则子板块用单独规则（如不强制下滑期），否则维持当前一级「房地产单独降级为下滑期」。需先确认申万 2021 版中房地产下具体 L2/L3 名称与代码。 |

---

## 小结

| 优化项 | 主要数据来源 | 关键接口/字段 | 积分 |
|--------|--------------|----------------|------|
| 相对资金 | Tushare | sw_daily：float_mv / total_mv | 5000 |
| 业绩预告/PMI | Tushare | forecast / express；cn_pmi（已用） | 2000/5000 |
| 资本开支 | Tushare | cashflow：c_pay_acq_const_fiolta | 2000/5000 |
| 房地产子板块 | Tushare | index_classify(L2/L3) + index_member_all | 2000 |

以上接口均为 Tushare 官方文档说明，积分与权限以站内最新为准。实现时需在采集脚本与规则引擎中增加对应字段与分支，并注意限频与批量拉取方式（可参考现有 `sync_industry_from_sw`、`collect_industry_cycle_data` 的 Tushare 调用方式）。
