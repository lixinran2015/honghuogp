## 板块龙头识别规则说明（4+2 简化版 v0.2）

> 目标：用尽量少但信噪比高的指标，在每个板块内识别出「空间龙头 / 补涨龙 / 相对强势 / 跟风」，写入 `fact_sector_leader_snapshot`，并服务主线雷达、启动替代路径、板块周期等功能。优先保证：**好解释、好调参、贴盘面**。

---

### 一、视角与数据来源

**识别维度**：以「时间窗口 + 板块」为基本视角。

- **时间窗口（window_id）**
  - 默认：`current_rolling_30d` = 过去 30 个交易日（含当日）。
  - 后续可扩展：`rolling_10d` / `rolling_60d` 等，但本版以 30 日窗口为基准。

- **数据来源**
  - `fact_daily_price_qfq`：日线行情（收盘价、涨跌幅、换手率、成交额、市值等）。
  - `fact_stock_sector` + `dim_sector`：股票与行业/题材板块映射。
  - 可选增强（非必需）：
    - `fact_stock_startup_candidate`：如需结合「启动确认日」加强时序判断。
    - `fact_money_flow`：后续可用于加强强度判断（本简化版先不强依赖）。

简化版的前提：**不追求指标“越多越好”，只保留对龙头判断最关键的 4 个主指标 + 2 个辅助约束。**

---

### 二、「4+2」指标体系总览

- **4 个主指标（直接参与强度和角色判断）**
  1. 空间高度：`ret_window`
  2. 连板强度：`continuous_limit`
  3. 成交活跃：`avg_amount`
  4. 启动时序：`first_start_date` / `start_order_in_sector`

- **2 个辅助约束（做过滤 & 修正，不单独打分）**
  1. 近期状态：`recent_strength`（最近 5 日涨幅 + 放量情况）
  2. 风险过滤：`liquidity_ok / is_risky`（ST、退市、极端缩量等）

下面分别说明。

---

### 三、4 个主指标的定义

#### 1. 空间高度（ret_window）

**定义：**

- 在窗口期内，从窗口起点价到窗口最后一日收盘价的累计涨幅：
  \[
  ret\_window = \frac{P_{end}}{P_{start}} - 1
  \]
  - `P_start`：窗口首日（或 30 日前）收盘价；
  - `P_end`：窗口末日收盘价。

**直觉：**

- 一个板块里面，空间龙头通常是这段时间「**走得最高**」的那只，而不是只看单日谁涨停。

#### 2. 连板强度（continuous_limit）

**定义：**

- 窗口期内，最大连续涨停天数：
  - 从 `fact_daily_price_qfq.change_pct` 中识别涨停日（例如 `change_pct >= 9.5%`）；
  - 统计所有连续涨停段的长度，取最大值。

**直觉：**

- 3 连板 > 2 连板 > 1 板；即便总涨幅类似，有连续强封的票，在实盘里更容易被市场认可为「空间总龙头」。

#### 3. 成交活跃（avg_amount）

**定义：**

- 窗口内日均成交额：
  \[
  avg\_amount = \text{mean}(\text{amount}_{window})
  \]

**直觉：**

- 真正的龙头一般是资金的「主战场」，日均成交额应该足够大；  
- 过低成交额的票，即便涨幅很高，也更像「小票行情」，不宜作为板块龙头重点跟踪。

#### 4. 启动时序（first_start_date / start_order_in_sector）

**定义（简化版本）：**

- `first_start_date`：窗口内第一次出现「明显起爆」的日期，可用以下近似：
  - 首次突破窗口前高；
  - 首次单日涨幅 ≥ 7%；
  - 或首次连续两日总涨幅 ≥ 12%；
  - 如果存在 `fact_stock_startup_candidate` 的启动确认日，可优先使用该日期。
- `start_order_in_sector`：在同板块内，将所有有 `first_start_date` 的股票按时间排序后的序位（越小表示越先启动）。

**直觉：**

- 一般而言，空间龙头是「**最早往上打的一批**」，补涨是其后出现的同题材/同赛道接力，晚很久且高度有限的，只能归为跟风。

---

### 四、2 个辅助约束的定义

#### 1. 近期状态（recent_strength）

为避免只看过去 30 日整体，却忽视「最近几天已经明显退潮」的情况，引入一个轻量的近期状态指标：

- `recent_ret_5d`：最近 5 日累计涨幅；
- `recent_amount_ratio`：最近 5 日平均成交额 / 过去 20 日平均成交额。

据此可以做一个简单标签：

- `recent_strength = strong`：
  - `recent_ret_5d >= 5%` 且 `recent_amount_ratio >= 1.5`
- `recent_strength = weak`：
  - `recent_ret_5d <= 0` 或 `recent_amount_ratio <= 0.8`
- `recent_strength = neutral`：其余情况。

> 用途：  
> 不直接参与基础 `leader_score` 计算，但在最终角色判定时，用来**下调已经明显退潮的股票权重**。

#### 2. 风险过滤（liquidity_ok / is_risky）

在正式判定之前必须做一层硬过滤：

- `liquidity_ok`：
  - 日均成交额不得低于一定阈值（例如 `avg_amount >= 5e7`，也可按市值分档调整）；
  - 最近一段时间（如 10 日）内无长时间一字跌停或极端缩量。
- `is_risky`：
  - ST、*、退市标志；
  - 明确被风控剔除的股票。

所有 `liquidity_ok = False` 或 `is_risky = True` 的股票，在龙头识别中直接排除。

---

### 五、板块内部强度排序（简化 leader_score）

在完成过滤后，在同一 `sector_code + window_id` 的候选股票中定义一个简单的强度得分：

```text
leader_score = 0.5 * score_ret
             + 0.3 * score_limit
             + 0.2 * score_liquidity
```

其中：

- `score_ret`：由 `ret_window` 映射而来：
  - 0–20% → 0–40 分线性；
  - 20–60% → 40–80 分线性；
  - ≥60% → 80–100 分，封顶。

- `score_limit`：由 `continuous_limit` 映射：
  - `continuous_limit >= 3`：90–100 分；
  - `continuous_limit == 2`：75 分左右；
  - `continuous_limit == 1`：60 分左右；
  - `continuous_limit == 0`：视为 40 分以内。

- `score_liquidity`：由 `avg_amount` 映射（按绝对值或板块内分位数）：
  - 板块内成交额最高的一档给 80–100 分；
  - 次一档给 60–80 分；
  - 很小成交额给 40 分以下。

**注意：**

- 启动时序与近期状态在简化版中不直接进入公式，而是在**角色划分时作为规则约束**使用，以保持可解释性。

---

### 六、角色划分规则（同一板块内）

在每个 `sector_code + window_id` 内，按 `leader_score` 降序排列后，根据「强度 + 时序 + 近期状态」划分角色。

#### 1. 空间龙头（absolute_leader）

**候选条件：**

- `leader_score` 排名第 1；
- `ret_window >= 40%`；
- `continuous_limit >= 2`，或在板块内 `ret_window` 明显高于第 2 名（例如高出 ≥10pct）。

**时序与近期状态约束：**

- 启动不是极端靠后：
  - `start_order_in_sector` 不在板块内末尾（例如不超过总数的 80% 分位）；
- `recent_strength != weak`（最近至少不是明显退潮）。

**标记：**

- `leader_type = 'absolute_leader'`
- `leader_rank = 1`

如无股票满足上述条件，可允许该板块本窗口期**没有空间龙头**。

#### 2. 补涨龙（catch_up）

在排除空间龙头后，从剩余股票中选 1–2 只补涨龙：

**基本条件：**

- `ret_window >= 25%`；
- `leader_score` 在板块内前 2–4 名；

**相对约束：**

- 启动时间晚于空间龙头（`first_start_date > leader_first_start_date`），或者空间高度明显低一档；
- `recent_strength = strong` 或 `neutral`（仍在轮动中，而非已经明显退潮）。

**标记：**

- `leader_type = 'catch_up'`
- `leader_rank = 2,3,...`

如果板块内没有空间龙头，但有一只空间 + 连板都明显领先的股票，也可以直接将其作为「相对空间龙头」（仍标记为 `absolute_leader`），补涨龙按相对关系定义。

#### 3. 相对强势（rel_strength / resilient）

对那些没有达到龙头/补涨标准，但在板块内明显抗跌、走势稳健的股票：

**示例条件：**

- `ret_window >= 15%`；
- 最近最大回撤适中（例如 `< 20%`）；
- 没有极端追高形态（大阴线砸回去）。

**标记：**

- `leader_type = 'rel_strength'` 或 `resilient`（二者的具体划分可按回撤/波动再细分）。

#### 4. 跟风（follower）

所有未被以上三类吸收的「跟随上涨」股票统一标记为跟风：

- 有一定涨幅，但：
  - 空间高度不够，或
  - 启动时间明显落后，或
  - 近期明显退潮（`recent_strength = weak`），或
  - 成交活跃度远低于板块均值。

**标记：**

- `leader_type = 'follower'`

在实现 4+2 简化规则时，建议每条 `(window_id, sector_code, ts_code)` 至少写入：

- `window_id`：如 `current_rolling_30d`
- `sector_code` / `ts_code` / `stock_name`
- `leader_type`：`absolute_leader / catch_up / rel_strength / resilient / follower`

其余可扩展字段（如 `limit_days / recent_strength / start_order_in_sector`）可存入 JSON 或额外列，但不作为简化版的硬依赖。

   - 第一步：实现一个 `SectorLeaderDetector`（仅使用 4+2 指标），先生成一个新 window_id（如 `rolling_30d_v2`）的龙头快照，离线对照实盘盘面。

## 板块龙头识别规则说明（草案 v0.1）

> 目标：为 `fact_sector_leader_snapshot` 提供一套「可落地、可调整」的正式识别规则，用真实行情数据在每个板块内识别出：空间龙头 / 补涨龙 / 相对强势 / 跟风，供主线雷达、启动替代路径、板块周期等统一使用。


总体目标
在每个板块内，用真实行情数据，稳定识别出：空间龙头 / 补涨龙 / 相对强势 / 跟风，并写入 fact_sector_leader_snapshot，供「主线雷达」「启动筛选替代路径」「板块周期」等统一使用。

一、数据输入 & 视角设定
时间窗口（window_id 对应逻辑）

当前 current_rolling_30d：过去 30 个交易日（含当日）。
后续可以支持 rolling_10d、rolling_60d 等，但先以 30 日为基准。
基础数据表

fact_daily_price_qfq：日线（收盘价、涨跌幅、换手、流通市值等）。
fact_stock_sector + dim_sector：股票–板块映射（industry / concept）。
可选增强：
fact_stock_startup_candidate：是否有启动信号、启动时间。
fact_money_flow：主力净流入。
二、核心指标定义（单票）
在每个板块内、指定窗口中，对每只股票计算一组统一指标：

空间高度相关

ret_window：窗口起点（30 日前）到当前的累计涨幅。
ret_from_low：窗口内从最低价到当前价的涨幅（辨别是否做过完整一轮）。
max_ret：窗口内最大涨幅（最高价/起点价 - 1）。
连板 & 强势程度

continuous_limit：窗口内最大连续涨停天数。
limit_days：窗口内涨停天数总数。
recent_limit：最近 N 日（如 5 日）是否有涨停。
成交与换手

avg_amount：窗口内日均成交额。
peak_amount：窗口内最大成交额。
avg_turnover：窗口均值换手率。
recent_amount_ratio：最近 3 日成交额 / 过去 20 日均值。
启动时序

first_start_date：第一次爆发点（定义之一）：
第一次突破 30 日高点；
或第一次连续两日涨幅 > X%（如 7%）。
start_order_in_sector：在板块内按 first_start_date 排序后的序位（谁先动）。
可用 fact_stock_startup_candidate：如果有「启动确认日」，优先取。
风险过滤

剔除：
长期跌停、流动性极差；
ST、退市风险等。
三、板块内角色判定规则（单板块）
1. 候选集合
对某个 sector_code + window_id：
过滤出窗口内涨幅明显、成交活跃的股票：
ret_window >= 20%
avg_amount >= 1e8（可按市值分档）
过去 30 日有至少 1 次涨停或连续大阳（如 2 日 > 12%）
2. 评分函数（综合强度得分）
为每只候选股算一个 leader_score，主要包括：

空间高度分 (40%)

score_ret = f(ret_window, max_ret)，如：
0–50% → 0–30 分线性；
超过 100% 则封顶。
连板与强势分 (30%)

score_limit：
continuous_limit >= 3 → 高分；
有多次涨停 → 加分；
最近 5 日有涨停 → 再加分。
成交与换手分 (20%)

score_liquidity：
日均成交额越大越好（但过分巨量可轻微扣分为「博弈末期」）。
recent_amount_ratio > 2 → 表示有明显放量，适度加分。
启动时序分 (10%)

score_timing：
在板块内最早启动的一批，加分。
明显「后知后觉」的，只当补涨/跟风。
最终：

[ leader_score = 0.4 \cdot score_{ret} + 0.3 \cdot score_{limit} + 0.2 \cdot score_{liquidity} + 0.1 \cdot score_{timing} ]

3. 角色标签规则
在一个板块内，按 leader_score 降序排好之后：

空间龙头（absolute_leader）

条件：
排名第 1；
ret_window >= 40%；
continuous_limit >= 2 或 max_ret >= 60%；
启动时间不是明显最后才动。
标记：
leader_type = 'absolute_leader'
leader_rank = 1
补涨龙（catch_up）

在剩余股票中，选「空间高度略低，但仍然强势」的 1–2 只：
ret_window >= 25%
leader_score 排名前 2–3，且排在龙头之后；
启动时间明显晚于龙头，或
市值/价格段与龙头不同（给另一条资金线的补涨空间）。
标记：
leader_type = 'catch_up'
leader_rank = 2,3,...
相对强势（rel_strength / resilient）

不够格做补涨龙，但在板块内位置靠前，且走势抗跌：
ret_window >= 15%
回撤小于一定阈值。
标记：
leader_type = 'rel_strength' 或 resilient
跟风（follower）

其它涨幅中等、启动时间靠后、连板弱的：
ret_window >= 10% 但 leader_score 较低；
或虽有一笔脉冲但很快回落。
标记：
leader_type = 'follower'

### 一、数据视角与适用范围

本规则适用于按「时间窗口 + 板块」识别龙头角色：

- **时间窗口（window_id）**
  - 默认：`current_rolling_30d`（过去 30 个交易日，含当日）。
  - 可扩展：`rolling_10d`、`rolling_60d` 等，不影响本文核心思路。

  - `fact_daily_price_qfq`：日线，含收盘价、涨跌幅、换手率、成交额、市值等。
  - `fact_stock_sector` + `dim_sector`：股票–板块（行业/题材）映射。
  - 可选增强：
    - `fact_stock_startup_candidate`：如需结合「启动信号」与龙头识别。
    - `fact_money_flow`：主力净流入指标。

本规则的输出写入 `fact_sector_leader_snapshot`，替换/增强当前简单的示例填充逻辑（按 rank 机械打标签）。

---

### 二、单票指标体系（在板块–窗口内）

对于某个 `window_id + sector_code`，在窗口期内对每只股票计算统一指标，用于后续角色判定：

1. **空间高度相关**
   - `ret_window`：窗口起点到当前的累计涨幅（默认用窗口首日或 30 日前的收盘价）。
   - `ret_from_low`：窗口内从最低价到当前价的涨幅，用于识别是否已经走完一轮。
   - `max_ret`：窗口内最高价相对起点价的最大涨幅。

2. **连板与强势程度**
   - `continuous_limit`：窗口内最大连续涨停天数。
   - `limit_days`：窗口内涨停总天数。
   - `recent_limit`：最近 N 日（例如 5 日）是否有涨停或接近涨停的大阳线。

3. **成交与换手活跃度**
   - `avg_amount`：窗口内日均成交额。
   - `peak_amount`：窗口内单日最大成交额。
   - `avg_turnover`：窗口内日均换手率。
   - `recent_amount_ratio`：最近 3 日平均成交额 / 过去 20 日平均成交额，用于识别近期是否有明显放量。

4. **启动时序（在板块内部的「谁先动」）**
   - `first_start_date`：第一波启动时间的近似定义：
     - 方案一：首次突破 30 日高点的交易日；
     - 方案二：首次出现连续两日总涨幅 > 12% 的起点；
     - 若存在 `fact_stock_startup_candidate` 的「启动确认日」，可优先使用。
   - `start_order_in_sector`：在同板块内按 `first_start_date` 升序的排序位置（谁先启动，谁后启动）。

5. **风险过滤**
   - 剔除：
     - 长期跌停、持续缩量、极端流动性不足的票；
     - ST、退市风险等特殊处理股票。

上述指标不要求一次性全部实现，可以逐步演进，但需要在代码中统一封装（例如 `SectorLeaderDetector` 内部使用）。

---

### 三、板块内部的综合强度评分（leader_score）

在某个板块–窗口内，先筛出「候选」再综合打分：

#### 1. 候选过滤规则

对同一 `sector_code + window_id` 的全部成分股，先做一层宽松过滤：

- `ret_window >= 20%`（窗口期内有一定涨幅）；
- `avg_amount >= 1e8`（日均成交额达到一定规模，可按市值分档调整）；
- 窗口内至少满足其一：
  - 有 1 次以上涨停（`limit_days >= 1`）；
  - 或出现连续两日总涨幅 > 12% 的「脉冲」。

只有通过这一步的股票才进入后续的评分和角色判定。

#### 2. 综合强度得分（leader_score）构成

对每个候选股，计算一个 `leader_score`，由以下部分加权构成：

1. **空间高度分（约 40% 权重）**
   - 依据 `ret_window` 和 `max_ret`：
     - 0–50% → 0–30 分线性；
     - 50–100% → 渐进趋缓；
     - 超过 100% 则封顶，避免极端样本碾压一切。

2. **连板与强势分（约 30% 权重）**
   - 依据 `continuous_limit`、`limit_days`、`recent_limit`：
     - 连板越多分越高（例如 3 板以上直接给高分）；
     - 多次涨停或多次接近涨停加额外分；
     - 最近 5 日内有涨停/大阳进一步加分。

3. **成交与换手分（约 20% 权重）**
   - 依据 `avg_amount`、`recent_amount_ratio`、`avg_turnover`：
     - 日均成交额越大，基础分越高，但对极端巨量略有限制（防止末期博弈）；
     - 最近 3 日放量明显（`recent_amount_ratio > 2`）加分；
     - 换手率在合理区间（不过度缩量，也不过度疯转）给予正向得分。

4. **启动时序分（约 10% 权重）**
   - 依据 `start_order_in_sector`：
     - 在板块内**最早启动**的一批（如前 20%）加分；
     - 明显后知后觉（起爆在板块整体启动很久之后），时序分较低。

一个可能的形式（示意）：

\[
leader\_score = 0.4 \cdot score\_{ret} + 0.3 \cdot score\_{limit} + 0.2 \cdot score\_{liquidity} + 0.1 \cdot score\_{timing}
\]

具体分数映射可在实现时以配置形式调整。

---

### 四、角色标签判定规则（同一板块内）

在完成候选过滤和 `leader_score` 计算后，对每个板块内部做角色划分。

#### 1. 空间龙头（absolute_leader）

在每个 `sector_code` 内，选出 0–1 只「空间龙头」：

- 排名条件：
  - `leader_score` 排名第 1；
- 硬性约束（可调）：
  - `ret_window >= 40%`；
  - 且满足以下之一：
    - `continuous_limit >= 2`（至少二板）；
    - 或 `max_ret >= 60%` 且最近仍保持强势。
- 时序约束：
  - 启动顺序不应是板块内明显最后一批（`start_order_in_sector` 不在末尾）。

符合条件的标记为：

- `leader_type = 'absolute_leader'`
- `leader_rank = 1`

若没有任何股票满足硬性条件，可以允许该板块暂时**没有绝对龙头**。

#### 2. 补涨龙（catch_up）

在去除空间龙头后，从剩余候选中选出 1–2 只「补涨龙」：

- 基本条件：
  - `ret_window >= 25%`；
  - `leader_score` 在板块内前 2–3 名；
- 相对约束：
  - 启动时间晚于空间龙头（`first_start_date` 更靠后）；
  - 在空间高度和连板上略逊一筹，但仍明显强于一般跟风。

标记：

- `leader_type = 'catch_up'`
- `leader_rank = 2,3,...`

#### 3. 相对强势（rel_strength / resilient）

对那些没达到空间龙头/补涨龙标准，但在板块内仍明显抗跌或走势稳健的股票：

- 条件示例：
  - `ret_window >= 15%`；
  - 最大回撤在合理范围内（如 `< 20%`）；
  - 没有极端追高或瀑布回落。

标记：

- `leader_type = 'rel_strength'`（趋势稳健型）或 `resilient`（抗跌型），可根据回撤/波动细分。

#### 4. 跟风（follower）

板块中其他表现中等或偏后的上涨股票：

- 不满足上述任一角色条件；
- 或虽短期拉升但：
  - 启动时间明显落后；
  - 无显著连板/放量特征；
  - 回撤较大。

统一标记：

- `leader_type = 'follower'`

### 五、写回 `fact_sector_leader_snapshot` 的字段建议

在实际落地时，建议为每条 `(window_id, sector_code, ts_code)` 记录写入以下关键信息：

- 基本信息：
  - `ts_code` / `stock_name`
  - `sector_code` / `sector_name`
  - `window_id`（如 `current_rolling_30d`）
- 角色与排序：
  - `leader_type`：`absolute_leader / catch_up / rel_strength / resilient / follower`
  - `leader_rank`：同一板块内排序名次（1 为最高）。
- 空间与涨幅：
  - `period_return_pct`：窗口期累计涨幅。
  - `max_return_pct`：窗口内最大涨幅（可选）。
  - `max_drawdown_pct`：窗口内最大回撤（可选）。
- 连板与强势：
  - `continuous_limit`：最大连续涨停天数。
  - `limit_days`：窗口内总涨停天数（可选）。
  - `recent_limit`：最近 N 日是否有涨停（可选）。
- 流动性：
  - `avg_amount`：日均成交额。
  - `avg_turnover`：日均换手率（可选）。
  - `recent_amount_ratio`：近期放量比（可选）。
- 启动时序：
  - `first_start_date`：第一波启动日。
  - `start_order_in_sector`：在板块内的启动顺序（可存为整型）。
- 综合评分：
  - `score`：`leader_score`，用于调参与前端展示。

这些字段大部分已经在当前表结构中以某种形式存在（如 `period_return_pct / continuous_limit / score`），可在现有基础上扩展或复用。

### 六、落地与演进建议

为了平滑过渡，建议分两步实施：

1. **离线评估版（新 window_id）**
   - 新增一个检测类（例如 `SectorLeaderDetector`），实现上述指标计算和角色判定逻辑。
   - 在 `backend/scripts/data_fill/` 下新建脚本（如 `rebuild_sector_leaders_from_kline.py`），针对最近一段历史（如最近半年）生成 `rolling_30d_v2` 版本的 `fact_sector_leader_snapshot`。
   - 对比：
     - 你直觉中的「板块龙头 / 补涨 / 跟风」 vs 算法输出标签；
     - 根据回测与肉眼观察调整各部分权重和阈值。

2. **替换线上 window_id / 接入主线雷达**
   - 当算法表现稳定后：
     - 用新算法维护 `current_rolling_30d`，或
     - 在主线雷达、替代路径、板块周期等模块中显式改用 `rolling_30d_v2`。
   - 所有使用 `fact_sector_leader_snapshot` 的模块（例如：
     - `StartupSectorAnalyzer`（主线雷达）；
     - `alternative_core_path_checker`（替代核心路径）；
     - `MarketEnvironmentAnalyzer._get_leader_startup_days`（板块周期）；
     ）都将自动受益于更精确的角色标签。

### 七、与现有逻辑的关系（现状说明）

当前项目中的 `fill_sector_leaders()`（`backend/scripts/data_fill/fill_sector_leaders_and_events.py`）主要用于示例/占位：

- 按每个行业随意取前几只股票，用简单顺序赋值：
  - 第 1 只：`absolute_leader`
  - 第 2 只：`catch_up`
  - 其余：`follower`
- `period_return_pct / continuous_limit / score` 等字段使用固定示例数值，未基于真实回测逻辑计算。

因此，在该脚本未被新算法替换前：

- 「主线雷达」中展示的「空间龙头 / 补涨龙 / 跟风」只是把现有 `leader_type` 翻译出来；
- 并不一定符合你实盘中对「谁是真龙头、谁是补涨、谁是纯跟风」的直觉；
- 本文档就是为**替换这部分示例逻辑**提供一个正式的总体设计蓝本，后续可以按此逐步实现与迭代。
