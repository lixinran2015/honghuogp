## 二、主线雷达

### 2.1 功能定位

主线雷达用于**按板块聚合启动信号**，识别当日市场的热点主线和次主线。

**数据来源：**
- `fact_stock_startup_candidate`：启动候选信号表
- `fact_sector_leader_snapshot`：板块龙头快照（4+2规则计算）

### 2.2 处理流程

```
步骤1: 取出窗口内启动候选信号（score≥阈值，stage为confirmed/started）
         │
步骤2: 按行业/概念聚合统计（日信号数、活跃天数、平均得分）
         │
步骤3: 获取板块龙头角色（空间龙头/补涨/跟风）
         │
步骤4: 计算板块强度分数 = 近3日信号数×2 + 不同股票数×0.5 + 趋势方向×1
         │
步骤5: 组装「接力链条」：为每个板块选出代表个股（最多6只）
         │       ├─ 按角色优先级排序（空间龙头 > 补涨龙 > 相对强势 > 跟风）
         │       └─ 近期走弱（5日涨幅≤0）的会被降级
         │
步骤6: 补全无候选板块但有真实空间龙头的板块（避免遗漏高标龙头）
```

### 2.3 板块强度计算

```python
# 强度分数 = 近3日爆发程度 + 宽度 + 趋势方向
strength_score = recent_3d_signals * 2.0 + distinct_stock_count * 0.5 + trend * 1.0

# 趋势方向 = 近3日信号数 - 前3日信号数（升温为正，降温为负）
trend = recent_3d_signals - prev_3d_signals
```

### 2.4 接力角色映射

| leader_type | 近期强弱 | 角色 | 优先级 |
|------------|---------|------|--------|
| absolute_leader | 强（5日涨幅>0） | 空间龙头 | 400 + cl |
| absolute_leader | 弱（5日涨幅≤0） | 相对强势 | 200 + cl |
| catch_up | 强（5日涨幅>0） | 补涨龙 | 300 + cl |
| catch_up | 弱（5日涨幅≤0） | 相对强势 | 200 + cl |
| follower | 任意 | 跟风 | 100 + cl |

**重要说明：** 近期走弱（5日涨幅≤0）的股票会被降级，不再显示为"空间龙头"或"补涨龙"。

## 三、4+2规则

### 3.1 规则概述

4+2规则是识别板块龙头的核心算法，存储在 `fact_sector_leader_snapshot` 表中，window_id = "rolling_30d_v2"。

### 3.2 4个核心指标

| 指标 | 说明 |
|-----|------|
| ret_window | 窗口期（30日）涨幅 |
| continuous_limit | 最大连板数 |
| avg_amount | 窗口期平均成交额 |
| first_start_date | 首次启动日期 |

### 3.3 2个约束条件

| 约束 | 说明 |
|-----|------|
| recent_strength | 近期强弱：5日涨幅 > 0 |
| liquidity_ok | 流动性：平均成交额 ≥ 阈值 |

### 3.4 龙头角色识别

```python
# 综合评分 = 涨幅归一化 × 0.4 + 成交额归一化 × 0.3 + 市值归一化 × 0.3

# 龙头类型判定：
absolute_leader  # 综合评分最高 + 近期走强 → 空间龙头
catch_up         # 涨幅次高 + 成交额放大明显 → 补涨龙
rel_strength     # 板块普跌时，跌幅最小的 → 相对强势
resilient        # 普跌板块中的抗跌代表
follower         # 其他有涨幅的股票
```

### 3.5 假龙头过滤

在识别「刚启动龙头」之前，先进行流动性风险检查：

| 过滤项 | 阈值 | 目的 |
|-------|------|------|
| 平均换手率 | ≤ 50% | 过滤一字板、异常交易 |
| 日均成交额 | ≥ 0.5亿 | 确保流动性 |
| 连板数 | ≤ 3板 | 拦截高位妖股，只保留刚启动 |

## 四、龙头跟踪池

### 4.1 功能定位

龙头跟踪池用于**持久化存储**被识别为"空间龙头"或"刚启动龙头"的股票，支持：
- 历史龙头保留（动态过期：7-35天）
- 自动退潮机制
- AI智能评分与买点识别
- 数据质量监控

### 4.2 数据表结构

**fact_leader_tracking_pool：**

| 字段 | 说明 |
|-----|------|
| ts_code | 股票代码 |
| is_space | 是否空间龙头 |
| is_new | 是否刚启动龙头 |
| first_space_date | 首次成为空间龙头日期 |
| first_new_date | 首次成为刚启动日期 |
| last_seen_date | 最近出现日期 |
| sectors | 所属板块列表 |
| continuous_limit | 历史最大连板数 |
| score | AI评分分数 |
| grade | AI评分等级 |

### 4.3 入池条件

**空间龙头入池：**
- 来自主线雷达的 `space_leaders_lead` 列表
- leader_type = "absolute_leader" 且 近期走强

**刚启动龙头入池：**
```python
leader_type in ("absolute_leader", "catch_up")  # 空间龙头或补涨
continuous_limit <= 3                           # 连板不超过3板
15% <= period_return_pct <= 120%                # 30日涨幅在合理区间
```

### 4.4 动态过期时间

基础过期时间为21天，根据情绪周期动态调整：

| 情绪周期 | 调整天数 | 最终过期时间 |
|---------|---------|-------------|
| 主升期/高涨期 | +7 | 28天 |
| 震荡期 | 0 | 21天 |
| 退潮期/低迷期 | -7 | 14天 |
| 冰点期 | -14 | 7天 |

```python
base_days = 21
emotion_adjust = {"主升期": +7, "高涨期": +7, "震荡期": 0, "退潮期": -7, "冰点期": -14}
expire_days = max(7, min(35, base_days + emotion_adjust[cycle]))
```

### 4.5 实时状态覆盖与退潮判定

查询时用当日主线雷达结果覆盖持久化数据：

```python
# 1. 从持久化表读取基础数据
pool_list = 查询 fact_leader_tracking_pool

# 2. 获取当日实时状态（范围查询最近5天）
analyzer_result = 调用主线雷达分析（最近5天）
current_state_map = 构建当日状态映射

# 3. 用实时状态覆盖并判定退潮
for item in pool_list:
    was_space = item.is_space  # 保存历史状态
    was_new = item.is_new

    if item.ts_code in current_state_map:
        state = current_state_map[item.ts_code]
        item.is_space = state["is_space"]      # 实时覆盖
        item.is_new = state["is_new"]
        item.continuous_limit = state["continuous_limit"]
    else:
        item.is_space = False                   # 当日不在雷达中
        item.is_new = False

    # 退潮判定：曾经是龙头，现在失去地位，且5日涨幅<=0
    is_retreat = (was_space or was_new) and not (item.is_space or item.is_new)

# 返回分类结果
- active_pool: 当前仍是龙头的股票
- retreat_pool: 退潮股票（近3日）
```

## 五、退潮判定

### 5.1 退潮信号指标

退潮判定基于4个加权信号：

| 信号 | 权重 | 说明 |
|-----|------|------|
| deep_drawdown | 0.35 | 深度回调：从近期高点回撤超过8% |
| break_ma20_persist | 0.30 | 持续跌破MA20：连续2日收盘价低于MA20 |
| volume_price_divergence | 0.20 | 量价背离：价格微涨/平但成交量萎缩超过20% |
| shrink_volume_down | 0.15 | 缩量下跌：价格下跌且成交量萎缩 |

### 5.2 退潮等级

```python
retreat_score = (
    deep_drawdown * 0.35 +
    break_ma20_persist * 0.30 +
    volume_price_divergence * 0.20 +
    shrink_volume_down * 0.15
)

if retreat_score >= 0.5:   retreat_label = "退潮风险"  # 建议卖出
elif retreat_score >= 0.3: retreat_label = "震荡"      # 观望
else:                      retreat_label = "强势"      # 可持有
```

### 5.3 AI评分过滤

**重要：有退潮风险的股票会被排除在AI评分之外**

```python
for stock in pool:
    if stock.get("retreat_label") == "退潮风险":
        continue  # 跳过该股票，不参与评分
```

## 六、数据质量监控

### 6.1 监控项

| 监控项 | 说明 | 告警阈值 |
|-------|------|---------|
| 同步成功率 | 每日是否完成同步 | 未完成：CRITICAL |
| 龙头数量异常 | 过多或过少 | =0: CRITICAL, >50: WARNING |

| 最高连板数 | 监管风险提示 | ≥10板: NOTICE |
| 市场情绪 | 基于涨跌停数据 | 高涨/低迷/弱势/正常 |

### 6.2 健康分数

```python
# 满分100分，根据告警扣减
health_score = max(0, min(100, 100 - 扣减 + 加分))

# CRITICAL: -30分
# WARNING: -15分
# NOTICE: -5分
```

## 七、常见问题

### 7.1 过期龙头仍显示

**症状：** 某股票已经走弱，但仍出现在龙头跟踪列表

**排查：**
1. 检查 `fact_sector_leader_snapshot` 中该股票的 leader_type 和 change_pct_5d
2. 确认 `last_seen_date` 是否过期（动态过期时间7-35天）
3. 确认实时状态覆盖后 `is_space` 和 `is_new` 是否为 False

### 7.2 显示的历史连板数不正确

**症状：** 某股票显示"4板"，但当前已不再是4板状态

**原因：** 早期实现使用历史最大连板数而非当前连板数

**修复：** 现在从 `fact_sector_leader_snapshot` 获取当前连板数

### 7.3 1板龙头不显示

**症状：** 法尔胜、国晟科技等1板龙头不显示

**原因：** 单日查询可能遗漏刚启动的龙头

**修复：** 使用范围查询（最近5天）确保1板龙头能被识别

### 8.2 简化记录

**2026-04-08 简化：**

| 改动 | 原实现 | 新实现 | 代码变化 |
|-----|--------|--------|---------|
| 日期查询范围 | 单日查询 | 5天范围查询 | - |
| 同步机制 | 5层（bootstrap/replay/catch_up/force/sync） | 1层（直接同步） | -48行 |

**设计原则：**
1. **实时优先**：每次调用都实时同步，不依赖缓存
2. **幂等操作**：同步操作幂等，多次执行结果一致
3. **简化状态**：减少持久化状态，增加实时计算
