# 🔧 数据库导入错误解决方案

## ❌ 错误信息

```
psql:database_backup.sql:67619: error: backslash commands are restricted; only \unrestrict is allowed
```

## 🔍 问题原因

这个错误发生在以下情况：

1. **使用 URI 连接格式**：当使用 `psql -d "postgresql://user:password@host/db"` 时，psql 默认会限制反斜杠命令的执行
2. **备份文件包含反斜杠命令**：备份文件中包含 `\copy`、`\set`、`\restrict` 等 psql 元命令
3. **安全限制**：PostgreSQL 为了安全，在使用 URI 连接时默认限制这些命令

## ✅ 解决方案

### 方案1: 使用传统连接参数（已修复）

脚本已修改为使用传统连接方式：

```batch
psql -U 用户名 -h 主机 -p 端口 -d 数据库名 -f 备份文件.sql
```

**优点**：
- 支持所有反斜杠命令
- 兼容性好
- 密码通过环境变量传递（安全）

### 方案2: 手动执行命令

如果脚本仍有问题，可以手动执行：

#### PowerShell

```powershell
# 设置密码环境变量
$env:PGPASSWORD = "qazwsx"

# 导入数据库（使用传统参数）
psql -U postgres -h localhost -p 5432 -d quantitative_trading -v ON_ERROR_STOP=0 -f database_backup.sql

# 清除密码
Remove-Item Env:PGPASSWORD
```

#### CMD

```cmd
set PGPASSWORD=qazwsx
psql -U postgres -h localhost -p 5432 -d quantitative_trading -v ON_ERROR_STOP=0 -f database_backup.sql
set PGPASSWORD=
```

#### 如果 psql 不在 PATH 中

```powershell
$env:PGPASSWORD = "qazwsx"
"D:\devTools\postgreSQL\bin\psql.exe" -U postgres -h localhost -p 5432 -d quantitative_trading -v ON_ERROR_STOP=0 -f database_backup.sql
Remove-Item Env:PGPASSWORD
```

### 方案3: 使用 pg_restore（如果是自定义格式）

如果备份文件是 `.backup` 或 `.dump` 格式（pg_dump 的自定义格式），需要使用 `pg_restore`：

```powershell
$env:PGPASSWORD = "qazwsx"
pg_restore -U postgres -h localhost -p 5432 -d quantitative_trading -v database_backup.backup
Remove-Item Env:PGPASSWORD
```

### 方案4: 修改备份文件（不推荐）

如果必须使用 URI 格式，可以在备份文件开头添加：

```sql
\unrestrict
```

但这需要修改备份文件，不推荐。

## 📝 参数说明

### `-v ON_ERROR_STOP=0`

- **作用**：即使遇到错误也继续执行
- **原因**：备份文件中可能有一些警告或非致命错误，使用此参数可以继续执行
- **注意**：如果连接失败等严重错误，仍会停止

### `-U, -h, -p, -d` 参数

- `-U`：数据库用户名
- `-h`：数据库主机
- `-p`：数据库端口
- `-d`：数据库名称

这些是传统连接方式，完全支持反斜杠命令。

## 🔍 验证导入

导入完成后，验证数据：

```powershell
# 检查表数量
psql -U postgres -d quantitative_trading -c "\dt"

# 检查数据量
psql -U postgres -d quantitative_trading -c "SELECT COUNT(*) FROM dim_stock;"
```

## ⚠️ 常见问题

### Q1: 为什么使用 URI 格式会限制反斜杠命令？

**A**: 这是 PostgreSQL 的安全特性。URI 连接方式通常用于应用程序连接，不允许执行 psql 的交互式命令。

### Q2: 使用环境变量传递密码安全吗？

**A**: 
- 在命令行中，环境变量是相对安全的方式
- 密码不会出现在进程列表中（使用 URI 格式时密码会出现在命令行）
- 执行后立即清除环境变量

### Q3: 导入时有很多警告，正常吗？

**A**: 
- 如果使用 `-v ON_ERROR_STOP=0`，警告不会停止导入
- 一些反斜杠命令的警告可以忽略
- 只要最后显示成功，数据应该已经导入

### Q4: 如何判断导入是否成功？

**A**: 
1. 检查退出代码（errorlevel）
2. 验证表是否存在：`psql -U postgres -d quantitative_trading -c "\dt"`
3. 检查数据量：`psql -U postgres -d quantitative_trading -c "SELECT COUNT(*) FROM dim_stock;"`
