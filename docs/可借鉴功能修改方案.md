## 三、具体修改方案

### 3.1 TradingView 图表嵌入

**目标**：个股详情、主题轮动等页面使用专业 K 线、技术指标、热力图。

**实现要点**：

1. **TradingView 小部件**（免费、可嵌入）
   - [TradingView Widget 文档](https://www.tradingview.com/widget/)
   - 支持：K 线、技术指标、Symbol Info、Market Overview（热力图）等

2. **A 股代码映射**：TradingView 使用 `SSE:600519`、`SZSE:000001` 等格式
   - 需在前后端维护 `ts_code` ↔ TradingView symbol 的映射

3. **落地页面**：
   - 个股诊断页 `StockDiagnoseView`：替换或补充 MiniChart 为 TradingView 日K
   - 主题轮动页 `ThemeRotationView`：增加板块涨跌幅热力图
   - 达尔文页 `DarwinView`：个股卡片可点击展开 TradingView 详情

**依赖**：无额外后端依赖，纯前端嵌入 iframe 或 TradingView 提供的 script 标签。

---

### 3.2 板块热力图

**目标**：直观展示各板块涨跌幅分布。

**方案 A**：TradingView Market Overview Widget
- 需确认是否支持申万/东财板块（部分为指数，可能有对应标的）

**方案 B**：自建热力图
- 使用 ECharts 或类似库，数据来自 `fact_sector_daily`、资金流向
- 与现有数据源完全契合，可控性强

**推荐**：方案 B 自建，数据用 `get_sector_moneyflow`、`fact_sector_daily` 等已有接口。

---

### 3.3 全局命令面板 (Cmd/Ctrl+K)

**目标**：通过 Cmd/Ctrl+K 快速搜索股票、行业、功能入口。

**实现要点**：

1. **组件选型**：
   - Vue 可使用 `cmdk`（OpenStock 同款）或 `@headlessui/vue` + 自定义
   - 参考：`vue-cmdk`、`kobalte` 等

2. **搜索范围**：
   - 股票：调用 `/api/stock-search` 或现有股票列表接口
   - 行业/板块：`dim_sector`、行业龙头列表
   - 功能入口：推荐池、启动监控、达尔文、9:40 监控等路由

3. **快捷键**：监听 `keydown`，`metaKey/Ctrl + K` 打开

4. **放置位置**：在 `App.vue` 或 `TopBar` 中全局挂载，点击「搜索」或按快捷键弹出

**落地**：在 `frontend-vue` 新增 `CommandPalette.vue`，集成到根布局。

---

### 3.4 用户偏好（中长期）

**目标**：根据风险偏好、关注行业等，个性化推荐与达尔文筛选。

**实现要点**：

1. **数据模型**：在用户表或单独 `user_preferences` 表增加：
   - `risk_tolerance`：保守/稳健/进取
   - `preferred_industries`：关注行业列表
   - `investment_goal`：短期/中长期/长期

2. **影响范围**：
   - 推荐服务：过滤或加权用户关注行业
   - 达尔文策略：可结合偏好调整行业周期阈值或展示顺序
   - 行业周期配置：用户偏好可作为「建议维度」输入（见行业周期智能化方案）

3. **前置条件**：需有用户体系（登录、多用户），当前若为单用户可先简化为本地配置存储。

---

### 3.5 每日个性化摘要（中长期）

**目标**：按自选股/持仓推送每日摘要：板块新闻、龙头变动、资金流向等。

**实现要点**：

1. **数据来源**：
   - 板块新闻：`SectorNewsService`、AkShare 东方财富
   - 龙头变动：`dim_industry_leader` 及相关接口
   - 资金流向：`data_warehouse/moneyflow`

2. **触发方式**：
   - 定时任务：闭市后（如 18:00）生成摘要
   - 可接入现有 `DataScheduler` 或参考 Inngest 做事件驱动

3. **推送渠道**：
   - 站内：新增「每日摘要」页面或 Dashboard 卡片
   - 注：先站内，不采纳邮件/飞书/钉钉

4. **AI 增强**：可接入 `ai_analysis_service` 做摘要压缩或亮点提炼。

---

### 3.6 空闲时展示热门股

**目标**：Cmd+K 或搜索框未输入时，展示近期热门股票，便于发现。

**实现要点**：

1. **数据来源**：
   - 近期涨停：`fact_limit_up_daily` 或涨停板接口
   - 资金流入：资金流向 Top N
   - 龙头股：`dim_industry_leader` 或板块领涨
   - 可选：股吧人气榜、推荐池 Top

2. **展示形式**：在 CommandPalette 或搜索下拉中，当 `keyword` 为空时展示「热门」分组

3. **更新频率**：可缓存 5–15 分钟，与现有数据更新节奏一致

**落地**：与 Cmd+K 命令面板一并实现，共用搜索组件。

---

### 3.7 个人化价格/事件提醒

**目标**：在自选股/持仓上设置价格提醒、突破提醒、财报提醒等。

**实现要点**：

1. **提醒类型**：
   - 价格提醒：涨破/跌破某价位
   - 突破提醒：突破 N 日新高/新低
   - 财报提醒：年报/季报披露日前 N 天

2. **数据模型**：`user_alerts` 或 `watchlist_alerts` 表，字段含 ts_code、alert_type、threshold、enabled

3. **检测方式**：
   - 价格/突破：定时任务（如每 5 分钟）或收盘后批量检测
   - 财报：基于 Tushare 财报日历，提前 N 天推送

4. **推送渠道**：仅站内通知（不采纳邮件/飞书/钉钉）

**前置条件**：若为单用户，可用 localStorage 或简单配置表；多用户需与自选股/持仓关联。

---

### 3.8 公司简介/财务 Widget

**目标**：个股详情页嵌入公司简介、财务概览小部件。

**实现要点**：

1. **方案 A**：TradingView Symbol Info Widget
   - 支持 A 股（SSE/SZSE 格式），可嵌入
   - 自带行情、简介、财务概要

2. **方案 B**：自建 Widget
   - 数据来源：Tushare `stock_basic`、`fina_indicator`，项目数据库
   - 展示：公司名称、行业、主营、ROE、营收增速、PE/PB 等

3. **落地页面**：`StockDiagnoseView`、`StockFinancialView`，或新建个股详情页

**推荐**：优先 TradingView Symbol Info（零后端开发），若 A 股支持不足则用方案 B。

## 五、不采纳项及原因

| 项目 | 原因 |
|------|------|
| Finnhub 作为主数据源 | 免费版仅美股，A 股需 Tushare/AkShare |
| 邮件/飞书/钉钉推送 | 不采纳，先做站内通知 |
| Next.js 技术栈迁移 | 当前 FastAPI + Vue3 稳定，迁移成本高 |
| MongoDB 替代 PostgreSQL | 现有数据仓库与业务深度绑定 |
| Better Auth | 当前若为单机/内网，可延后统一认证方案 |
