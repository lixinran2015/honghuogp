# 选股与买入优化方案

基于 AI 复盘报告（2026-02-27）提出的改进点，结合当前代码结构给出的落地优化方案。

---

## ⚠️ 重要：各买入入口与生效范围

| 买入入口 | 数据来源 | 是否经过 stock_recommender | 是否受 trading_rules 限制 |
|----------|----------|----------------------------|---------------------------|
| **达尔文页** | Darwin 长线筛选 + refine_darwin_candidates | ❌ 否 | ❌ 否（bypass_trading_rules=true） |
| **自选/观察** | 用户自建列表 | ❌ 否 | ❌ 否 |
| **操作池-搜索添加** | 任意股票搜索 | ❌ 否 | ❌ 否 |
| **操作池-图片识别** | 截图解析 | ❌ 否 | ❌ 否 |
| **StockCard**（热点/启动等） | 各场景列表 | ❌ 否 | ❌ 否 |
| **推荐池** | process_started_stocks / AI精选 | ✅ 是 | ❌ 否 |

**结论**：若大部分买入来自 Darwin、自选、搜索等，则对 `stock_recommender` 和 `trading_rules_config` 的修改**基本不会影响你的实际操作**。要改进「非智能推荐」买入，需在对应入口（如 Darwin 精炼）或 `create_holding` 统一做校验。

---

## 一、复盘报告核心结论

| 问题 | 建议 |
|------|------|
| 持仓14只，略显分散 | 聚焦 3-5 只强势股 |
| 清仓胜率 40.9% | 提高选股成功率，减少无效交易 |
| 亏损多因单日追高/入场即转弱 | 加强买入前趋势和量价确认 |
| 盈利多为 1-3 天短期持有 | 坚持短线纪律，及时止盈止损 |
| 监控池暂无标的 | 现有持仓管理优先，汰弱留强 |

## 二、智能选股优化

### 2.1 提高入池门槛

**文件**: `backend/services/recommendation/stock_recommender.py`

```python
# 当前
MIN_SCORE_FOR_RECOMMENDATION = 75

# 建议：提高到 80，减少低质量推荐
MIN_SCORE_FOR_RECOMMENDATION = 80
```

**效果**: 只推荐七维总分 ≥ 80 的股票，提高选股胜率。

---

### 2.2 强化追高过滤

**文件**: `backend/services/recommendation/stock_recommender.py`

```python
# 当前：启动确认日前 5 日涨幅 > 35% 不入池
MAX_CHANGE_5D_BEFORE_ENTRY_PCT = 35.0

# 建议：降到 25%，更严格避免买在短期高点
MAX_CHANGE_5D_BEFORE_ENTRY_PCT = 25.0

# 当前：近 20 日自最低价涨幅 > 60% 视为第二波不入
MAX_GAIN_FROM_LOW_20TD_PCT = 60.0

# 建议：降到 50%，更早排除已有一波的票
MAX_GAIN_FROM_LOW_20TD_PCT = 50.0
```

---

### 2.3 新增：单日涨幅过滤（避免单日追高）

**文件**: `backend/services/recommendation/stock_recommender.py`

在 `_add_to_recommendation` 中，在追高过滤后增加：

```python
# 单日追高过滤：启动确认日当日涨幅 > 7% 不入池（或涨停不入）
change_pct_today = float(stock_data.get('change_pct', 0) or 0)
if change_pct_today > 7.0:
    logger.info(
        "跳过单日追高: %s 启动确认日=%s 当日涨幅%.1f%% > 7%%",
        candidate.ts_code, entry_date, change_pct_today
    )
    return False
```

---

### 2.4 提高趋势确认权重

**文件**: `backend/services/stock/stock_filter_service.py` - `refine_darwin_candidates`

```python
# 当前：财务60% + 趋势25% + 板块15%
final_score = (
    base_score_norm * 0.6 +
    trend_s * 0.25 +
    sector_s * 0.15
)

# 建议：趋势30% + 财务55% + 板块15%，强化趋势确认
final_score = (
    base_score_norm * 0.55 +
    trend_s * 0.30 +
    sector_s * 0.15
)
```

**说明**: 复盘指出「入场时机选择不佳」，加强趋势权重有助于减少逆势买入。

---

### 2.5 趋势差时直接过滤（达尔文精炼）

**文件**: `backend/services/stock/stock_filter_service.py`

当前逻辑：趋势差（`trend_s < 0.3`）时，`allow_no_kline=True` 仍会放行。建议对达尔文推荐也严格过滤：

```python
# 在 refine_darwin_candidates 中，即使 allow_no_kline=True
# 若 trend_s < 0.4 且 base_score_norm < 0.75，也过滤掉（避免财务好但趋势差的票）
if trend_s is not None and trend_s < 0.4 and base_score_norm < 0.75:
    logger.debug(f"达尔文过滤: {stock.code} 趋势差({trend_s:.2f})且财务非顶尖")
    continue
```

## 三、买入改进

### 3.1 降低每日新开仓上限（减少无效交易）

**文件**: `backend/config/trading_rules_config.py`

```python
# 当前：每日新开仓上限 9 笔（过高）
MAX_NEW_POSITIONS_PER_DAY = 9

# 建议：降到 2-3 笔，符合「减少无效交易频率」
MAX_NEW_POSITIONS_PER_DAY = 2
```

---

### 3.2 操作池聚焦（3-5 只）

**文件**: `backend/services/accounts/holdings_service.py`

```python
# 当前
POOL_MAX_SIZE = 8

# 建议：降到 5-6，与复盘「聚焦3-5只强势股」一致
POOL_MAX_SIZE = 5
```

---

### 3.3 新增：买入前追高风险校验（自动化买入路径）

若有从推荐池自动加入操作池的逻辑，需在**加入前**做追高风险检查：

**文件**: `backend/services/accounts/holdings_service.py` 或新建 `backend/services/accounts/buy_validator.py`

```python
# 在 create_holding（bypass_trading_rules=False）中，新开仓前增加：
# 1. 获取该股实时行情和 K 线
# 2. 调用 ChaseRiskService.calculate_chase_risk
# 3. 若 chase_risk_score > 65，拒绝开仓，理由为「追高风险较高，建议等待回调」
```

**注意**: 手动添加（`bypass_trading_rules=True`）不触发此校验。

---

### 3.4 量价确认（推荐池入池时）

**文件**: `backend/services/recommendation/stock_recommender.py` - `_add_to_recommendation`

在 `stock_data` 验证通过后增加：

```python
# 量价确认：量比 < 1.2 或 换手率 < 2% 时，不入池（缺乏量能配合）
amount = float(stock_data.get('amount', 0))
avg_amount = float(stock_data.get('avg_amount_20d', 1))
turnover = float(stock_data.get('turnover_rate', 0))

volume_ratio = amount / avg_amount if avg_amount > 0 else 0
if volume_ratio < 1.2 and turnover < 2.0:
    logger.info(
        "跳过量价不足: %s 量比=%.2f 换手=%.1f%%，缺乏量能配合",
        candidate.ts_code, volume_ratio, turnover
    )
    return False
```

## 六、对「非智能推荐」买入真正有效的优化

若主要从 **达尔文、自选、搜索** 等入口买入，以下方向才有实质作用：

### 6.1 达尔文精炼（已保留）

**文件**：`backend/services/stock/stock_filter_service.py` - `refine_darwin_candidates`

- **趋势权重**：25% → 30%，财务 60% → 55%
- **影响**：达尔文页的排序和展示顺序，趋势更强的股票会靠前
- **未改动**：达尔文仍不拦截添加，仅影响列表顺序

### 6.2 在 create_holding 增加「买入前提示」（不拦截）

对所有添加（含 bypass=true）在服务端算一次追高风险，将结果返回给前端，由前端决定是否弹出提示，**不强制拒绝**。这样可覆盖 Darwin、自选、搜索等所有入口。

### 6.3 在 Darwin 精炼中增加硬过滤（可选）

若希望达尔文列表更严，可在 `refine_darwin_candidates` 中增加：

- `trend_s < 0.4` 直接过滤
- 或当日涨幅 > 7% 不展示

这样达尔文页本身就不会出现明显追高的标的，从源头减少误买。

### 6.4 推荐池优化（仅影响推荐池）

`stock_recommender` 的 MIN_SCORE、追高过滤等，仅影响「推荐池/监控池」的入池结果。若经常从推荐池选股，可再考虑提高门槛；否则对主流程影响有限。

---

## 七、总结

1. **路径要分清**：手动添加全部走 `bypass_trading_rules=true`，交易规则不会生效；推荐池逻辑只影响推荐池本身。
2. **对非推荐买入**：达尔文精炼的「趋势权重」已调整；要进一步约束，可在 Darwin 精炼加硬过滤，或在 create_holding 做追高风险提示（不拦截）。
3. **复盘建议**：聚焦 3–5 只、减少无效交易、加强趋势和量价确认，更适合通过 **达尔文精炼更严** 和 **操作池池满提示更早** 来实现，而不是依赖推荐池和交易规则。
